# 작업 지시서: 수능 수학 "점수 해부" 모바일 웹앱 v1 시제품

## 0. 한 줄 요약

종이로 친 수능 수학 모의고사의 답 30개를 폰에서 터치로 넣으면, 채점해서 점수를 나눠 보여 주고(점수 해부) 먼저 고칠 것 2~3개(계단)를 알려 주는 모바일 웹앱 시제품을 만든다. 빈 폴더에서 시작해 코드, 테스트, 화면 캡처 검증, 문서, 최종 보고까지 한 번에 끝내는 것이 목표다.

## 1. 진행 방식

- 중간에 멈춰서 묻지 말고 끝까지 진행한다. 판단이 필요한 곳은 이 문서의 원칙에 맞춰 정하고 보고서에 "내가 정한 것"으로 적는다.
- 아래 결정은 여러 차례 검토를 거쳐 확정한 것이다. 임의로 바꾸지 않는다. 더 나은 안이 있으면 구현은 이 문서대로 하고 보고서에 제안으로만 적는다.
- 권장 순서: 계획, 계산 로직과 단위 테스트, 데이터와 상태, 화면, 자동 검증, 문서와 보고. 병렬로 나눌 수 있으면 나누되 문구와 디자인 값은 한 곳에서만 정의해 충돌을 막는다.
- 검증은 만든 쪽이 아닌 별도 검토 단계(가능하면 다른 에이전트)가 맡는다.
- 모든 보고와 문서는 한국어로, 결론을 먼저, 짧게 쓴다.
- 실행해서 확인한 수치만 보고한다. 재지 않은 것(예: 사람이 답을 넣는 데 걸리는 시간)을 잰 것처럼 쓰지 않는다.
- 현재 작업 폴더 아래에 score-anatomy 폴더를 만들어 그 안에서 작업한다. git init 후 단계별로 커밋한다(원격 없음). 저장소를 새로 만들거나 외부로 올리지 않는다.

## 2. 배경

- 만드는 사람: 컴퓨터공학 전공 대학생. 팀과 예산이 작다.
- 사용자: 고등학생(주로 고2, 2028학년도 수능 대비). 미성년자다.
- 쓰는 순간: 모의고사를 본 날 저녁, 폰 한 손. 시험지는 종이다.
- 이 시제품의 용도: 고2 8~10명 사용성 테스트. 답 입력 시간과 남은 오입력, 결과 화면을 잘못 읽는지를 잰다. 첫 실사용 목표는 2027년 3월 학력평가다.
- 시중 앱과 다른 점: 기출 앱은 태블릿과 펜이 전제이고, 채점 서비스는 배너가 많은 웹이다. 이 앱은 폰 한 손으로 답만 넣는 조용한 화면, 추정과 사실을 구분하는 정직한 숫자가 핵심이다.

## 3. 절대 원칙

1. 미성년자 보호: 다크 패턴, 연속 기록, 순위, 배지, 다른 학생과 비교, 불안을 건드리는 문구, 알림 권한 요청을 넣지 않는다.
2. 개인정보 최소: 가입, 로그인, 이름 입력이 없다. 기록은 이 기기의 브라우저 저장소에만 둔다. 서버 전송, 분석 도구, 광고가 없다. 실행 중 외부 네트워크 요청은 0건이어야 한다(글꼴과 스크립트도 프로젝트 안에 직접 싣는다).
3. 저작권: 시험 문제 원문과 그림을 싣지 않는다. 문항은 번호로만 가리킨다. 실제 기출 좌표, 실제 정답, 실제 등급컷을 지어내지 않는다. 예시 데이터는 화면에서도 "예시"라고 보이게 한다.
4. 정직한 숫자: 실제 점수는 채점 결과 그대로다. 자동 차감은 없다. 추정값에는 "추정" 배지와 "약"을 붙인다. 학생이 표시하지 않은 것을 단정하지 않는다(표시가 없는 정답을 "풀어서 맞힘"이라고 부르지 않는다).
5. 금지 문자: 화면 문구, 코드 주석, 문서, 커밋 메시지, 보고서 어디에도 줄표(U+2014, U+2013)와 가운뎃점(U+00B7, U+318D, U+30FB, U+2027)을 쓰지 않는다. 범위는 물결표(6~10점), 나열은 쉼표, 구분은 줄바꿈이나 배지로 한다. 화면 문구에는 느낌표와 이모지도 쓰지 않는다.
6. 정답 노출 금지: 학생이 "정답 보기"를 누르기 전에는 어떤 화면, 입력칸 안내문, 접근성 라벨에도 정답을 드러내지 않는다. 채점 결과는 맞음과 틀림만 보여 준다.

## 4. 기술 조건

- 백엔드 없는 정적 웹앱. Vite, React, TypeScript, Vitest, Playwright를 기본으로 한다. 환경 제약으로 불가하면 대안을 고르고 이유를 보고한다.
- 명령: npm run dev, npm run build(dist 정적 산출물), npm run build:single(모든 자산을 넣은 HTML 파일 1개), npm test(단위), npm run e2e(화면 흐름), npm run verify(아래 10장의 자동 검증 전체).
- 어떤 정적 호스팅이나 파일 하나로도 열리게 상대 경로와 해시 라우팅을 쓴다. 서비스 워커는 넣지 않는다.
- 상태 저장은 localStorage. 읽기와 쓰기를 try/catch로 감싸고, 저장이 안 돼도 화면은 동작한다. 저장 형식에 version 필드를 둔다.
- 글꼴: 일반 빌드는 npm의 pretendard 패키지에서 dynamic subset을 가져와 프로젝트에 직접 싣는다. 단일 HTML 빌드는 시스템 글꼴만 쓴다. 글꼴 스택 끝에는 -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", system-ui, sans-serif를 둔다. 외부 CDN은 금지다.
- 대상: iOS Safari와 Android Chrome 최신 2개 버전. 폭 360~430px 기준, 더 넓으면 가운데 정렬된 430px 칼럼. viewport에 확대 금지 설정을 넣지 않는다. 안전 영역(safe-area) 여백을 반영한다.
- 어두운 화면은 기기 설정(prefers-color-scheme)을 따른다. 앱 안 전환 버튼은 만들지 않는다. 움직임 줄이기 설정을 따른다.
- 시험 화면 구성을 코드에 박아 넣지 않는다. 문항 유형과 배점은 전부 시험 데이터에서 읽는다(6장).
- Playwright 브라우저를 내려받을 수 없으면 시스템에 설치된 크롬을 쓰고, 그것도 없으면 다른 방법으로 화면 캡처 검증을 한다. 검증을 건너뛰지 않는다. 정말 불가능하면 무엇이 왜 안 됐는지 보고한다.

## 5. 디자인 기준 (이름: 계측기)

숫자를 재서 보여 줄 뿐 평가하지 않는 도구처럼 보여야 한다.

색(밝은 화면, 어두운 화면 순):
- 배경 #FFFFFF, #111315
- 표면(카드, 입력 칸) #F4F5F7, #1B1E22
- 장식용 경계선 #D9DCE1, #2C3036
- 입력 테두리와 그래프 윤곽 #868C96, #7A818C
- 본문 글자 #17191C, #ECEEF1
- 보조 글자 #5B6168, #A4ABB5
- 포인트 #2747D4, #8FA8FF
- 포인트 위 글자 #FFFFFF, #0E1220
- 정답 #0B7A4B, #4CC38A
- 오답 #B93A1E, #FF8A75
- 경고 #8A5300, #F2B84B

글자(크기/줄 높이, 굵기):
- 주 숫자 56/60px, 700. 화면당 하나뿐인 숫자.
- 보조 숫자 28/34px, 600.
- 제목 22/30px, 700.
- 본문 16/24px, 400(버튼 글자는 600).
- 보조 14/20px, 400.
- 캡션 13/18px, 400. 이보다 작은 글자는 쓰지 않는다.
- 숫자에는 font-variant-numeric: tabular-nums. 크기는 rem으로 잡는다. 입력 칸 글자는 16px 이상.

간격과 모양:
- 간격은 4px 단위(주로 8, 12, 16, 24, 32). 화면 좌우 여백 20px.
- 모서리 12px(카드, 버튼), 8px(칩, 배지). 그림자 없음, 1px 경계선.
- 터치 영역은 모든 조작 요소에서 48x48px 이상, 요소 사이 8px 이상. 답 숫자 키는 높이 64px.
- 주 버튼은 화면 아래 고정, 높이 52px. 한 화면에 주 버튼은 하나.
- 전환은 150~200ms.

규칙:
- 한 화면에 주 숫자는 하나.
- 정답색과 오답색은 작은 표식과 짧은 글자에만 쓰고 반드시 기호나 글자를 함께 붙인다. 큰 숫자와 넓은 면에는 쓰지 않는다. 색만으로 뜻을 전하지 않는다.
- 막대와 표식은 색이 아니라 무늬로 가른다: 채움, 빗금, 윤곽만, 점선 윤곽.
- 캐릭터, 일러스트, 배너, 축하 효과가 없다. 진한 색 면적은 화면의 10% 이하.
- 팝업을 쓰지 않는다. 예외는 삭제 확인 대화상자와 바텀시트(설명, 답 고치기)뿐이다.

## 6. 데이터

시험 하나는 JSON 파일 하나다(src/exams 아래). 형식:

    {
      "id": "sample-a",
      "title": "예시 시험 A",
      "note": "1~21번 5지선다, 22~30번 단답형",
      "isSample": true,
      "isPast": false,
      "answerReleased": true,
      "items": [
        { "no": 1, "kind": "mc", "choices": 5, "points": 2, "answer": 3, "typeId": "t01" },
        { "no": 22, "kind": "short", "points": 3, "answer": 12, "typeId": "t07" }
      ],
      "cuts": {
        "source": "예시 값",
        "asOf": "2026-11-22",
        "confirmed": false,
        "grades": { "1": [88, 92], "2": [81, 85], "3": [72, 76] }
      },
      "types": {
        "t01": { "name": "지수와 로그", "coords": [ { "label": "예시 좌표", "itemNo": 9 } ] }
      }
    }

- kind는 mc(5지선다)와 short(단답형, 0~999 정수, 최대 3자리)다.
- cuts가 없으면 "등급컷 자료 없음" 상태로 처리한다.
- 예시 시험 3개를 만든다.
  - 예시 시험 A: 1~21번 mc, 22~30번 short. 배점은 1~3번 2점, 4~11번 3점, 12~21번 4점, 22~27번 3점, 28~30번 4점(합 100점). 등급컷은 위 형식의 예시 값.
  - 예시 시험 B: 배열이 섞인 경우. 1~15번 mc, 16~22번 short, 23~28번 mc, 29~30번 short. isPast는 true. 배점 합은 100점.
  - 예시 시험 C: answerReleased가 false인 경우(정답 공개 전 상태 시연용).
- 유형 이름은 교육과정 단원 수준으로 10개 안팎을 둔다(예: 지수와 로그, 삼각함수, 수열, 함수의 극한과 연속, 미분, 적분, 경우의 수, 확률, 통계). 예시 시험 A에서 14번, 20번, 21번은 적분, 15번과 29번은 수열, 9번과 11번은 확률, 27번은 통계로 둔다(7장 검산 예시와 맞추기 위함).
- 좌표는 실제 기출을 가리키는 것처럼 꾸미지 않는다. 예시 데이터에는 "예시 좌표"라는 라벨의 가짜 좌표만 넣는다. 실제 운영에서는 "2025학년도 6월 모의평가(2024년 6월 시행) 14번"처럼 학년도와 시행 연도를 함께 적은 문자열을 넣게 된다는 점을 문서에 적는다.

## 7. 계산 규칙

용어:
- 실제 점수 = 맞힌 문항 배점의 합.
- 표시: 5지선다 문항에 학생이 직접 붙이는 "고민" 또는 "찍음". 단답형은 "자신 없음"만 있고 계산에 쓰지 않는다. "고민"도 계산에 쓰지 않고 기록만 한다.
- 추측 표시 정답 점수 = "찍음" 표시가 있고 맞힌 5지선다 문항 배점의 합.
- 찍음 전체 배점 = "찍음" 표시가 있는 5지선다 문항(맞음과 틀림 모두) 배점의 합.
- 찍기 운을 평균으로 본 점수 = 실제 점수 - 추측 표시 정답 점수 + 0.2 x 찍음 전체 배점. 화면에는 반올림해서 "약 N점"으로, "추정" 배지와 함께 보여 준다. "찍음" 표시가 하나도 없거나 반올림 값이 실제 점수와 같으면 보여 주지 않는다.
- 실수 표시 오답 점수 = 틀린 문항 가운데 원인을 "풀 줄 아는데 틀렸어요"로 고른 문항 배점의 합. 이 점수는 실제 점수 안에 들어 있지 않다.
- 안 풂은 0점으로 채점하되 미입력과 구분한다. 미입력이 남아 있으면 채점하지 않는다(몰래 오답 처리 금지).

등급컷까지 남은 점수(목표 등급의 컷 범위가 lo~hi일 때):
- 첫 줄은 항상 실제 점수 기준이다. 실제 점수가 lo보다 작으면 "실제 78점 기준 3~7점 남았어요"(lo - 실제, hi - 실제). lo 이상 hi 이하면 "컷 범위 안이에요. 컷이 확정되면 이 화면이 바뀌어요." hi보다 크면 "컷 범위보다 위예요."
- 둘째 줄은 "찍음" 표시가 있을 때만: "찍기 운을 평균으로 보면 약 75점, 그 기준으로는 6~10점이에요"(반올림한 값으로 계산). 범위 안이나 위일 때의 문구도 같은 방식으로 만든다.
- 컷이 확정(confirmed가 true, lo와 hi가 같음)이면 범위 대신 한 숫자로 쓰고 배지를 "확정"으로 바꾼다.

계단(먼저 고칠 유형) 선정. 통계 없이 내 기록만으로 정한다:
- 유형별 점수 = 그 유형의 틀린 문항 배점 합 + "찍음" 표시 정답 배점 합.
- 점수가 큰 순, 같으면 문항 번호가 앞선 유형 순.
- 상위 2개를 보여 주고, 3위가 2위의 70% 이상이면 3개까지. 대상이 하나면 하나만. 없으면 빈 상태 문구.

검산 예시(반드시 단위 테스트와 "예시 결과 보기"에 그대로 쓴다). 예시 시험 A에 다음 응답을 넣는다:
- 틀린 문항 6개: 11번(3점), 15번(4점), 20번(4점), 21번(4점), 27번(3점), 29번(4점). 나머지 24문항은 정답.
- "찍음" 표시: 9번(3점, 정답), 14번(4점, 정답), 11번, 20번, 21번(틀림).
- 원인 "풀 줄 아는데 틀렸어요": 15번, 29번. 나머지 틀린 문항은 "풀이가 안 떠올랐어요".
- 기대값: 실제 78점, 맞힌 문항 24개, 추측 표시 정답 7점, 찍음 전체 배점 18점, 찍기 운을 평균으로 본 점수 74.6(화면에는 약 75점), 실수 표시 오답 8점, 그 외 오답 14점.
- 목표 2등급(컷 81~85): 첫 줄 3~7점, 둘째 줄 6~10점. 목표 1등급(88~92): 10~14점, 13~17점. 목표 3등급(72~76): "컷 범위보다 위예요".
- 계단: 적분 12점, 수열 8점, 확률 6점 순으로 3개.

## 8. 화면

흐름: 시작, 시험 선택, 답 입력, 입력 확인, 표시, 점수, 오답 원인, 점수 해부, 계단, 재풀이. 하단 탭은 "이번 시험"과 "기록" 2개뿐이다(답 입력 중에는 탭을 숨겨도 된다).

(1) 시작
- 한 줄 설명, "예시" 배지가 붙은 결과 미리보기 한 장, 주 버튼 "시험 고르기", 글자 버튼 "예시 결과 보기"(7장 검산 예시를 넣은 점수 해부 화면으로 바로 감). 지난 기록이 있으면 "이어서 보기".

(2) 시험 선택
- 최근 시험이 맨 위인 목록. 예시 시험에는 "예시" 배지, 정답 공개 전이면 "정답 공개 전" 배지.
- 시험을 고르면 질문 하나: "채점은 아직인가요?" 선택지 "아직 안 했어요", "이미 했어요". "이미 했어요"면 이후 표시를 "채점한 뒤 표시"로 따로 기록하고, 표시 화면과 결과 화면에 "채점한 뒤에 표시한 기록이에요"를 작게 적는다.
- isPast가 true인 시험에서만 한 번 더 묻는다: "이 시험지, 전에 풀어 본 적 있나요?" 선택지 "처음이에요", "일부 봤어요", "풀어 봤어요".
- 주 버튼 "답 넣기".

(3) 답 입력. 방식이 2가지이고 사용성 테스트에서 비교한다. 기본은 키패드 방식이다. 테스트 진행자용 화면이나 주소의 input 값(keypad, rows)으로 바꾼다. 두 방식은 같은 상태를 쓴다.

키패드 방식:
- 위: 뒤로 가기, 시험 이름, 글자 버튼 "전체 보기"(입력 확인 격자를 미리 엶).
- 진행 줄: "객관식 1~21번" 같은 구간 이름, "11문항 입력", 얇은 진행 막대.
- "지금 넣을 문항"과 큰 문항 번호(주 숫자 크기, 예: 12번), 옆에 배점 배지.
- 5칸 묶음 두 줄: 직전 묶음(넣은 답이 보임)과 현재 묶음. 현재 칸은 포인트색 테두리. 칸을 누르면 그 문항으로 간다.
- 안내 한 줄: "다섯 문항마다 시험지와 맞춰 보세요. 칸을 누르면 그 문항으로 가요."
- 아래 고정 키패드. 5지선다 문항이면 1~5 키(높이 64px)와 그 아래 "안 풂", "지우기". 키를 누르면 답이 들어가고 다음 문항으로 넘어간다. "지우기"는 한 칸 뒤로 가서 지운다.
- 단답형 문항이면 같은 틀에서 키패드만 0~9, "지우기", "안 풂", "다음"으로 바뀐다. 넣은 숫자를 크게 보여 주고, "다음"을 눌러야 확정되어 넘어간다(한 자리만 눌렀다고 넘어가지 않는다). 기기 기본 자판은 띄우지 않는다.
- 마지막 문항을 넣으면 입력 확인으로 간다.

5행 방식:
- 한 쪽에 5문항. 문항마다 한 줄에 번호와 1~5 원(라디오 그룹 의미 구조, 터치 영역 48px 이상). 같은 줄의 다른 답을 누르면 그 문항만 바뀐다. 자동으로 넘기지 않는다.
- 단답형 줄은 누르면 아래에 앱 자체 숫자 키패드가 열린다.
- 문항 번호를 누르면 "안 풂"과 "입력 지우기"를 고를 수 있다.
- "이전"과 "다음 5문항"은 화면 아래 고정. 위쪽 요소를 줄여 360x640 화면에서도 5줄과 버튼이 스크롤 없이 보이게 한다.

(4) 입력 확인
- 제목 "넣은 답을 확인해 주세요", 안내 "시험지와 5개씩 맞춰 보세요."
- 30칸 격자(5열). 칸마다 문항 번호와 넣은 답. 안 풂은 "안 풂", 미입력은 강조 테두리와 "미입력".
- 칸을 누르면 그 문항의 답을 고치는 바텀시트(문항 유형에 맞는 키패드).
- 미입력이 남아 있으면 넘어가지 않고 첫 미입력 칸으로 옮기며 안내한다.
- 주 버튼 "맞아요, 다음으로".

(5) 표시(찍음과 고민)
- 질문 "풀이 없이 고른 문항이 있나요? 있으면 눌러 주세요. 점수는 그대로예요."
- 도움말 "시험지에 세모나 물음표를 쳐 둔 문항을 보면 쉬워요."
- 5지선다 문항만 격자로 보여 준다(번호와 넣은 답). 누를 때마다 표시 없음, 고민, 찍음, 표시 없음 순으로 바뀐다. 고민은 윤곽 무늬와 "고민" 글자, 찍음은 빗금 무늬와 "찍음" 글자.
- 범례 한 줄 "한 번 누르면 고민, 두 번 누르면 찍음, 세 번 누르면 지워져요."
- 단답형은 아래에 따로 한 줄로 번호만 보여 주고 누르면 "자신 없음"이 붙는다.
- 선택 질문 하나: "시간은 어땠나요?" 선택지 "충분했어요", "빠듯했어요", "몇 문제는 못 봤어요".
- 주 버튼 "채점하기", 보조 버튼 "없어요"(표시 없이 채점).
- 정답 공개 전 시험이면 채점 대신 답을 저장하고 "정답이 아직 공개되지 않았어요. 답은 저장해 뒀어요. 공개되면 여기서 바로 채점돼요."를 보여 준다.

(6) 점수
- 주 숫자(예: 78점)와 한 문장 "30문항 가운데 24문항을 맞혔어요."
- 주 버튼 "틀린 문항 살펴보기", 보조 "점수 해부 바로 보기", 글자 버튼 "입력 고치기".
- 점수가 낮아도 형식은 같다. 평가, 위로, 느낌표가 없다.

(7) 오답 원인
- 틀린 문항 목록: 번호, 배점, 내 답(안 풂 포함). 정답은 보여 주지 않는다.
- 문항마다 하나만 고른다: "풀 줄 아는데 틀렸어요", "풀이가 안 떠올랐어요", "잘 모르겠어요".
- 문항마다 글자 버튼 "정답 보기". 누르면 정답을 보여 주고 그 문항을 "정답 확인함"으로 기록한다.
- 전부 건너뛸 수 있다("건너뛰기"). 주 버튼 "점수 해부 보기".

(8) 점수 해부. 이 앱의 핵심 화면이다.
- 시험 이름(보조 글자), 주 숫자 78점, "30문항 가운데 24문항을 맞혔어요."
- 100점 막대(높이 28px). 왼쪽부터 표시 없이 맞힌 점수(채움), 추측했다고 표시한 정답(빗금), 실수라고 표시한 오답(윤곽만), 그 외 오답(점선 윤곽). 막대 아래 78 위치와 100 위치에 눈금 숫자. 그림 역할과 설명 라벨을 붙인다.
- 표시 행 두 줄만 둔다.
  - 빗금 표식, "추측했다고 표시한 정답", "7점", 보조 글자 "78점 안에 들어 있어요"
  - 윤곽 표식, "실수라고 표시한 오답", "8점", 보조 글자 "78점에는 들어 있지 않아요"
- 문장 "78점 가운데 7점은 찍었다고 표시한 문항에서 나왔어요. 틀린 22점 가운데 8점은 실수라고 표시했어요."
- 등급컷 상자(표면색).
  - 목표 등급 칩(시험 데이터에 있는 등급만). 고르기 전에는 질문 "어디까지 가는 계단을 볼까요?"
  - "2등급 컷 81~85점"과 "추정" 배지. 배지를 누르면 바텀시트로 출처와 기준일(예시면 "예시 값이에요").
  - 첫 줄(보조 숫자 크기): "실제 78점 기준 3~7점 남았어요"
  - 둘째 줄(본문 크기, 찍음 표시가 있을 때만): "찍기 운을 평균으로 보면 약 75점, 그 기준으로는 6~10점이에요"와 "추정" 배지. 펼침 설명 "찍었다고 표시한 문항을 운이 보통이었을 때로 다시 계산한 점수예요. 실제 점수는 78점 그대로예요."
  - 컷 자료가 없으면 "등급컷 자료를 기다리고 있어요. 점수와 고칠 것은 지금 볼 수 있어요."
- 주 버튼 "고칠 것 2가지 보기"(계단 수에 맞춘 숫자), 글자 버튼 "입력 고치기".
- 빈 상태: 표시가 없으면 행 대신 "표시한 문항이 없어서 나눠 볼 것이 없어요. 78점 그대로예요." 원인을 건너뛰었으면 실수 행 자리에 "아직 원인을 표시하지 않았어요"와 오답 원인 화면으로 가는 링크(0점이라고 쓰지 않는다).
- 쓰지 않는 것: 같은 크기 숫자 카드 4장, "진짜 점수" 같은 표현, "풀어서 맞힌 점수"라는 이름, 78에서 무언가를 뺀 숫자를 주 숫자처럼 보이게 하는 것.

(9) 계단
- 제목 "먼저 고칠 2가지"(개수에 맞춤). 유형 단위 카드, 최대 3장.
- 카드 내용: 유형 이름과 놓친 배점, 이유 한 줄, 할 일, 버튼 "다시 풀고 답 넣기", 접힌 설명 "순서를 정한 방법".
- 이유 한 줄은 기록에서 만든다. 예: "이번 시험에서 이 유형으로 8점을 놓쳤고, 둘 다 실수라고 표시했어요.", "이 유형의 14번은 찍어서 맞혔다고 표시했어요."
- 할 일의 첫째는 항상 오늘 시험지다: "오늘 시험지의 15번과 29번을 다시 풀기". 좌표가 있으면 둘째로 좌표 목록과 "좌표 복사" 버튼(예시면 "예시 좌표" 배지).
- 대상이 없으면 "틀린 문항이 없어요. 고칠 계단도 없어요."

(10) 재풀이
- 고른 계단의 오늘 시험지 문항을 하나씩, 큰 문항 번호와 문항 유형에 맞는 키패드로 다시 푼 답을 받는다.
- 맞혔고 정답을 본 적이 없으면 문장 "다시 풀어 맞혔어요."와 기록 라벨 "다시 풀어 맞힘"(원인이 실수였으면 "실수로 표시함, 다시 풀어 맞힘").
- 정답을 먼저 봤거나 "이미 했어요" 경로면 라벨 "정답 확인 후 다시 맞힘".
- 틀리면 "이번에도 답이 달랐어요. 이 유형을 계단에 남겨 둘게요."
- "실수 확인"이라는 표현은 쓰지 않는다. 같은 문항을 다시 맞힌 것만으로 처음 틀린 이유가 밝혀지지는 않는다.

(11) 기록
- 지난 시험 목록(시험 이름, 넣은 날짜, 점수), 항목 삭제, "이 기기의 기록 모두 지우기"(확인 대화상자 한 번).
- 준비 중 기능은 한 줄씩 자리만 둔다: "7일 뒤 확인", "실수 카드", "공유 리포트", "점수대별 정답률". 문구 "준비 중이에요." 점수대별 정답률은 "응답이 모이면 열려요."
- 맨 아래 작은 글자 링크 "테스트 진행자용".

(12) 테스트 진행자용(주소 #/test)
- 참가자 코드(P01 형식. 이름을 넣지 말라는 안내), 입력 방식 선택(키패드, 5행), 시험 선택, 시작.
- 자동 기록(이 기기 안에만): 화면별 진입 시각, 답 입력 시작과 완료 시각, 문항별 입력 횟수, 입력 확인에서 고친 문항 수, 표시 화면에 머문 시간, 시험 선택부터 첫 점수까지 걸린 시간.
- 정답지 대조: 진행자가 참가자에게 준 답지의 답 30개를 쉼표로 붙여 넣으면 참가자가 최종 제출한 답과 비교해 남은 오입력 수를 보여 준다.
- 내보내기: JSON과 CSV 파일 저장, 클립보드 복사. 네트워크 전송은 없다. 기록 초기화 버튼.

## 9. 문구

- 해요체. 한 문장에 한 가지. 사실과 다음 할 일만 말한다.
- 쓰지 않는 말: 잘했어요, 아쉬워요, 위험, 심각, 지금 안 하면, 뒤처져요, 남들은, 마지막 기회, 잠재 점수, 진짜 점수.
- "부족" 대신 "남았어요"를 쓴다.
- 버튼은 누르면 일어나는 일을 적는다("확인" 대신 "채점하기").
- 숫자: 범위는 "6~10점", 추정값은 "약 75점"(소수점 없음), 표본이 들어간 값에는 분모를 적는다(예: "8명 중 6명"). 표본이 없는 통계는 지어내지 않고 자리를 비운다.
- 문구는 한 파일에 모은다. 8장에 적은 문구는 그대로 쓴다.
- 오류와 빈 상태 문구: "14번이 비어 있어요. 안 푼 문항이면 '안 풂'을 눌러 주세요.", "답은 0부터 999까지예요.", "아직 넣은 시험이 없어요. 시험을 하나 넣으면 여기에 쌓여요.", "채점하지 못했어요. 답은 그대로 있어요."

## 10. 자동 검증 (npm run verify로 전부 실행하고 결과를 docs/검증결과.md에 남긴다)

1. 단위 테스트: 7장 검산 예시의 모든 기대값. 추가 경우(표시 없음, 전부 정답, 전부 안 풂, 컷 범위 안, 컷 범위 위, 컷 자료 없음, 확정 컷, 섞인 배열 시험 B).
2. 화면 흐름 테스트(390x844): 키패드 방식과 5행 방식 각각으로 예시 시험 A의 답 30개를 넣고 입력 확인, 표시, 채점, 오답 원인, 점수 해부, 계단, 재풀이까지 끝낸다. 점수 해부 화면에 78, 7점, 8점, 3~7점, 약 75점, 6~10점이 보이는지 확인한다. 시험 B와 C도 한 번씩 통과시킨다.
3. 작은 화면(360x640)에서 키패드 방식과 5행 방식 모두 조작 요소가 가려지거나 겹치지 않는지 확인한다.
4. 모든 화면에서 보이는 글자의 계산된 크기가 13px 이상인지 검사한다.
5. 모든 조작 요소의 터치 영역이 48x48px 이상인지 검사한다. 예외를 두려면 이유를 보고한다.
6. 실행 중 외부 요청이 0건인지 검사한다(자기 주소 밖으로 나가는 요청이 하나라도 있으면 실패).
7. 금지 문자 검사: 소스, 문서, 빌드 결과, 각 화면에 그려진 글자에 U+2014, U+2013, U+00B7, U+318D, U+30FB, U+2027이 없는지. 화면 문구에 느낌표와 이모지가 없는지.
8. 색 대비 계산: 글자와 바탕 조합은 4.5:1 이상, 입력 테두리와 그래프 윤곽은 3:1 이상(밝은 화면과 어두운 화면 모두).
9. 정답 노출 검사: "정답 보기"를 누르기 전에 화면 글자, 입력칸 안내문, 접근성 라벨 어디에도 틀린 문항의 정답이 나오지 않는지.
10. 화면 캡처: 모든 화면을 밝은 화면과 어두운 화면으로 찍어 docs/screens에 저장하고, 직접 열어 보고 어긋난 곳을 고친다.

검증에서 실패한 항목은 고치고 다시 돌린다. 끝내 못 고친 항목은 숨기지 말고 보고한다.

## 11. 산출물

- score-anatomy 폴더의 전체 코드와 커밋 기록.
- README.md: 실행 방법, 빌드 방법, 폰에서 여는 방법.
- docs/결정기록.md: 이 문서의 결정과 내가 정한 것.
- docs/시험_추가_방법.md: 시험 JSON 작성법, 시험 당일 정답과 등급컷을 넣는 절차, 좌표 표기 규칙.
- docs/사용성테스트_진행안내.md: 진행 순서, 입력 방식 2종을 같은 참가자에게 순서를 바꿔 쓰게 하는 방법, 측정 기록 내보내기, 아래 통과 기준(제안값이며 통계 검증이 아니라 방향 확인용이라고 적는다).
  - 답 입력: 중앙값 75초 이하, 남은 오입력이 있는 참가자 1명 이하.
  - 첫 점수까지: 도움 없이 180초 안에 도달한 참가자가 4명 중 3명 이상.
  - 표시 화면: 40초 이하, 감점되는 줄 알았다고 말한 참가자 1명 이하.
  - 읽기 질문 3개를 모두 맞힌 참가자가 5명 중 4명 이상: "실수라고 표시한 8점은 78점 안에 들어 있나요?"(아니요), "78점 가운데 찍었다고 표시한 문항에서 나온 점수는 몇 점인가요?"(7점), "약 75점은 무엇을 뜻하나요?"(찍기 운을 평균으로 본 추정).
- docs/검증결과.md와 docs/screens의 화면 캡처.
- 단일 HTML 파일(build:single 결과)과 프로젝트 전체 압축 파일. 위치를 보고한다. 사용자에게 파일로 전달하거나 아티팩트로 게시할 수단이 있으면 단일 HTML을 그렇게 전달해서 폰에서 바로 열 수 있게 한다.
