# iOS 앱 껍데기 결정 기록

작업 지시서 2(iOS 앱 껍데기), 작업 지시서 3-2(새 웹 묶음에 맞추고 다시 검증), 작업 지시서 4의 2부(최소 iOS 18, 시험 자료 받기와 서명 확인)에서 지시를 그대로 따른 것과, 지시에 없는 세부를 내가 정한 것을 이유와 함께 적어요. 3-2에서 정한 것은 4장, 작업 지시서 4에서 정한 것은 5장에 있어요. 웹과의 약속은 docs/앱_다리_규격.md 의 규격 1(1~6장)을 그대로 구현했어요. 같은 문서 7장의 규격 2(정해진 주소에서 받은 시험 자료를 remote 로 넘기기, saRemote)는 구현하지 않았고 작업 지시서 4의 몫이에요. 웹 묶음 0.3.1 은 규격 1과 2를 받아서(manifest 의 bridge 1, bridgeMax 2) 규격 1 껍데기에서도 그대로 돌아요.

## 2. 내가 정한 것

### 지시서 읽기

| 정한 것 | 이유 |
| --- | --- |
| 지시서 5-3 의 `window.SA_APP` 를 다리 규격의 `window.__SA_APP__` 로 읽었어요 | 다리 규격 문서와 웹 코드(src/platform/app.ts)가 `__SA_APP__` 를 쓰고, 지시서는 마크다운에서 밑줄 두 개가 굵은 글씨 표시로 사라진 것으로 보여요 |
| "큰 화면 하나"는 iPhone 17(402 x 874pt)로 정했어요 | SE(375 x 667pt)와 대비되는 일반 크기 화면이고, 웹 캡처(390 x 844)와 크기가 가장 가까워 나란히 비교하기 좋아요 |

### 싣기와 화면

| 정한 것 | 이유 |
| --- | --- |
| 파일 주소로 싣기(loadFileURL, 읽기 허용은 묶음 폴더 하나)를 그대로 썼어요. WKURLSchemeHandler 로 바꾸지 않았어요 | 묶음이 단일 HTML(스크립트와 스타일이 파일 안)이고 모듈 스크립트도 파일 안에 있어서, 파일 주소로도 화면 흐름 테스트가 모두 통과했어요. 바꿀 이유가 생기지 않았어요 |
| 웹뷰와 껍데기는 창이 뜬 뒤(RootView 의 onAppear)에 만들어요 | App 을 만들 때(앱이 다 켜지기 전) 웹뷰를 만들었더니 화면 테스트의 첫 누름에서 앱이 꺼졌어요(iOS 26.4 는 UIGestureRecognizer 의 누름 지연 처리, iOS 18.4 는 UIGestureGraph 의 검사에서 꺼짐). 웹뷰 설정을 하나씩 꺼도, 아주 단순한 HTML 을 실어도 꺼졌고, 만드는 때만 옮기자 두 OS 모두 고쳐졌어요. 실제 손가락 누름에서도 같은 일이 생겼을 가능성이 커서 껍데기 쪽에서 고쳤어요 |
| 웹에 알리기와 화면 확인에 WebKit 의 기본 API(evaluateJavaScript)만 써요. Swift 전용 함수(callAsyncJavaScript 의 Swift 판)를 쓰지 않아요 | iOS 26 SDK 의 Swift 전용 함수를 쓰면 앱이 /usr/lib/swift/libswiftWebKit.dylib 를 불러오는데, 이 파일이 iOS 18.4 에 없어서 앱이 켜지자마자 꺼졌어요(시뮬레이터에서 확인). iOS 17 도 같을 것으로 봐요. verify.sh 가 Release 바이너리에 이 라이브러리 연결이 없는지 확인해요 |
| 웹에 알리는 메시지는 JSON 을 그대로 자바스크립트 객체 글자로 넣어 `window.__saFromApp(...)` 을 불러요 | 메시지에는 영문 type, 숫자, 참거짓만 있어서 이스케이프 문제가 없고, 참거짓이 숫자(1, 0)로 바뀌지 않아요(웹은 ok === true 로 봐요). 단위 테스트가 JavaScriptCore 로 확인해요 |
| didFinish 전에 생긴 알림(storeFailed, copied)은 받은 차례대로 모아 두었다가 didFinish 에서 보내요. 새 문서를 싣기 시작하면 비워요 | 다리 규격 3장("didFinish 부터 불러요"). 앞 문서에 대한 알림이 새 문서로 가지 않게 해요 |
| 읽는 동안 바뀐 글자 크기는 didFinish 에서 다시 보내요 | 다리 규격 3장 |
| 새 문서를 만들기 전(다시 읽기, 웹 화면 프로세스가 끝난 뒤 다시 싣기)마다 `__SA_APP__` 스크립트를 지금 store.json 으로 다시 만들어요 | 켤 때의 기록으로 다시 읽으면 웹이 예전 기록을 바탕으로 저장해 새 기록을 덮어쓸 수 있어요. 받은 저장을 모두 마친 뒤에 읽어요 |
| 웹 화면 프로세스가 끝나면 지금 화면(# 포함)을 다시 싣고, 30초 안에 세 번 끝나면 실패 안내를 띄워요 | 메모리가 부족할 때 iOS 가 웹 화면 프로세스를 끝낼 수 있어요. 흰 화면으로 두지 않으려고요 |
| 실패 안내는 묶음 파일이 없을 때, 차단 규칙을 컴파일하지 못했을 때, 처음 싣기가 실패했을 때, didFinish 뒤 5초 동안 웹 화면(#root)이 비어 있을 때, 20초 안에 싣기가 끝나지 않을 때 띄워요 | 흰 화면 대신 안내를 보여 주려고요. 차단 규칙 없이는 싣지 않아요(통신 0 원칙을 지키는 쪽으로 실패) |
| 웹뷰와 그 뒤, 켤 때 화면(Launch Screen)을 토큰 배경색(#FFFFFF, #111315)으로 칠하고 상태 표시줄은 기본(밝기를 따름)으로 둬요 | 5-1 의 깜빡임 방지. 켤 때 화면은 색 자산(LaunchBackground, 어두운 화면 값 포함)으로 정했어요 |
| 웹뷰의 바깥 여백 조정(contentInsetAdjustmentBehavior)은 끄고 SwiftUI 에서는 안전 영역을 무시해요 | 위아래 여백은 웹이 env(safe-area-inset-*) 로 처리해요. 키보드가 올라와도 SwiftUI 가 웹뷰를 줄이지 않게 했어요(웹뷰가 스스로 맞춰요) |
| Safe Browsing(사기 사이트 경고), 전화번호 자동 링크를 끄고 자바스크립트가 창을 여는 것을 막아요. 새 창 요청, 카메라와 마이크, 기기 움직임 권한 요청은 모두 거절해요 | 바깥 조회와 권한 요청을 원천적으로 없애려고요 |
| Safari 웹 검사기(isInspectable)는 Debug 빌드에서만 켜요 | Release 에 숨은 기능을 두지 않으려고요 |

### 다리와 저장

| 정한 것 | 이유 |
| --- | --- |
| 저장은 같은 폴더의 임시 파일(.store-UUID.tmp)에 쓰고 디스크에 내린(fsync) 뒤 rename 한 번으로 바꿔치기해요. 실패하면 임시 파일만 지워요 | 중간에 앱이 꺼져도 store.json 은 예전 것이나 새것 둘 중 하나예요. 단위 테스트가 폴더 만들기, 쓰기, 바꿔치기 각 단계의 실패와 실제 쓰기 권한 없음에서 원래 파일이 그대로인지 봐요 |
| 저장 요청을 합치지 않고 받은 차례대로 하나씩 해요 | 단순해야 차례가 틀릴 일이 없어요. 기록 크기가 작아 한 번에 수 밀리초예요 |
| 보관 이름은 기기 시간대의 "store-보관-YYYYMMDD-HHMMSS.json" 이고, 같은 이름이 있으면 -2, -3 을 붙여요. 덮어쓰지 않는 이동(moveItem)을 써요 | 사람이 파일 앱 등에서 보더라도 언제 것인지 알 수 있게 했어요 |
| 보관할 store.json 이 없으면 보관은 성공으로 봐요 | 잃을 기록이 없어요. 이어지는 저장은 그대로 해요 |
| 보관에 실패하면 그 실행 동안의 저장은 하지 않고 storeFailed 로 알려요(다음 실행은 다시 시도해요) | 다리 규격 2장 |
| 저장 요청의 json 이 글자가 아니면 storeFailed, 복사 요청이 글자가 아니면 copied(ok: false) 로 답해요. 알 수 없는 메시지는 무시해요 | 다리 규격 2장의 "saCopy 하나에 copied 하나"를 지키고, 저장하지 못한 것은 알리려고요 |
| 주 화면(main frame)에서 온 메시지만 받아요 | 처음 문서만 싣지만 한 번 더 막아 둬요 |
| 저장과 보관 하나마다 백그라운드 시간("기록 저장")을 요청하고 끝나면 놓아요. 앱이 끝날 때(willTerminate)는 쌓인 저장이 끝날 때까지 기다려요 | 5-4 의 "뒤로 가거나 끝날 때 쓰던 저장이 끝나도록". 시간이 다 되면 한 번만 놓아요(단위 테스트) |
| 앞선 실행이 쓰다 남긴 임시 파일은 켤 때 지워요. 보관 파일과 store.json 은 건드리지 않아요 | 쓰다 꺼진 흔적이 쌓이지 않게 |
| 파일 보호 등급은 기본값(처음 잠금 해제 전까지 보호)을 그대로 써요 | 잠긴 채 뒤에서 저장이 끝나야 해서 "완전 보호"를 쓰지 않았어요 |

### 글자 크기, 햅틱, 복사

| 정한 것 | 이유 |
| --- | --- |
| fontScale 은 그 설정에서 시스템 본문 글자(.body)의 크기를 기본 크기(17pt)로 나눈 값이에요. 1보다 작으면 1, 2보다 크면 2 | 기기 설정과 같은 비율로 웹 글자가 커지게 하려고요. 값: 작은 설정 1, 큰 설정 19/17(1.118), 23/17(1.353, 가장 큰 일반 크기), 접근성 28/17(1.647), 33/17(1.941), 그보다 크면 2. 처음에는 UIFontMetrics.scaledValue 를 썼다가 가장 큰 일반 크기가 1.314 로 본문 글자보다 덜 커져서 바꿨어요 |
| 햅틱은 UIImpactFeedbackGenerator(light) 하나를 만들어 두고 누름마다 쓴 뒤 다음을 준비(prepare)해요. 웹뷰에 묶인 생성자(iOS 17.5 부터)를 늘 써요(최소 iOS 18, 작업 지시서 4) | 다음 누름의 지연을 줄이려고요. 시스템 햅틱을 끈 기기에서는 시스템이 알아서 울리지 않아요 |
| 복사가 됐는지는 클립보드의 changeCount 로만 봐요. 클립보드를 읽지 않아요 | 다른 앱의 내용을 읽는 것처럼 보이지 않게 하고, 붙여 넣기 허락 창이 뜨지 않게 하려고요 |

## 4. 작업 지시서 3-2에서 정한 것

작업 지시서 3-2(고침 2)의 지시는 그대로 따랐어요(브랜치 ios-sync, 다리 규격 1 유지, Release 에 새 장치 없음, 웹 파일 고치지 않음). 지시에 없는 세부를 아래처럼 정했어요.

### 시작과 버전

| 정한 것 | 이유 |
| --- | --- |
| 작업 폴더의 커밋하지 않은 문서 변경 4개(앞 요청에서 제가 고치던 README, 결정기록, 출시 준비, 실기기 확인표)는 지우지 않고 이름을 붙인 git stash 로 보관한 뒤 ios-sync 를 만들었어요 | 지시서는 커밋하지 않은 변경이 있으면 알리고 멈추라고 해서 처음에는 멈추고 알렸어요. 알린 글에 "시작하면 stash 로 보관한다"고 적었고 사람이 시작하라고 해서 그대로 했어요. 그 가운데 0.3.1 에도 맞는 내용(규격 범위, 작업 지시서 4의 통신, 배포용 모양 규칙, 웹 문서의 맞지 않는 곳)만 새로 적었어요 |

### 웹이 받은 이벤트와 누름 만들기

| 정한 것 | 이유 |
| --- | --- |

## 6. 확대 진단과 규격 2 받기 보완(2026-11-25)

- 사용자가 15:05 시작 점검 뒤 충전기 연결 없이 진행하도록 정했어요. 덮개를 연 맥에서 긴 실행은 caffeinate로 감쌌어요.
- 확대 진단은 0.3.2 시험용 묶음을 쓰고 조건은 실행 중인 문서에만 넣어요. 앱 시작 뒤 WKWebView가 먼저 보이고 웹 라우터가 아직 준비되지 않은 경우를 관찰했어요. 시험 화면이 그려졌는지 확인한 뒤 이동해요. 측정 전에 시작 시간 초과가 난 실행은 별도로 기록해요.
- 껍데기는 받은 목록의 서명을 먼저 보고 같은 발행물의 시험 파일을 동시에 최대 네 개 받아요. 개별 파일은 받은 바이트의 SHA-256과 id, rev를 확인한 뒤에만 임시로 남겨요. 다음 시도의 서명된 목록에 맞는 파일은 다시 검사한 뒤 사용할 수 있어요. 모두 통과하기 전에는 기존 시험 목록을 바꾸지 않아요.
- 앱을 뒤로 보내면 받던 요청을 취소하고, 앞으로 돌아오면 중단됐던 시도를 다시 해요. 최근에 자동으로 확인했더라도 사용자가 누른 새로 확인이 대기하면 처리해요. 주소나 키가 비었으면 시작할 때 웹에 넘기는 remote는 null이에요. 같은 키로 보관한 파일은 유지해요.
- 시험 내용과 잠금 달력은 웹이 다시 검사해요. 서명과 파일 검사를 통과한 새 판을 설치된 웹이 거부하면 그 시험이 목록에서 사라질 수 있어요. 학생이 넣은 답은 기기에 남아요. 발행자는 지원하는 가장 오래된 웹 묶음에서 새 판과 달력을 먼저 확인해야 해요. 웹과 다리 규격에 같은 id의 대체 판을 넘기는 방식은 정해지지 않았어요.
- 공개 키를 바꾸면 다른 키로 받은 판은 신뢰하지 않아요. 새 키의 첫 목록에는 이전에 발행한 모든 시험 id를 포함해야 해요. 깊이 64를 넘는 JSON도 현재 껍데기는 받지 않아요. 이 두 조건과 시험 내용 검사의 분담을 PC 쪽 발행 문서에 반영할 것을 제안해요.
- 웹뷰의 외부 통신은 계속 차단해요. 정해진 주소와 키가 있는 앱 껍데기만 시험 파일을 받아요. 받는 기능은 학생의 답이나 저장 기록을 보내지 않아요. 개인정보 표기 파일의 수집과 추적 항목을 검토했고 추가할 항목은 없었어요.
