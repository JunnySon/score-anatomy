# 시험 추가 방법

결론: 시험 하나는 JSON 파일 하나예요. 화면 구성(문항 수, 객관식과 단답형 배열, 배점, 등급 수)은 전부 이 파일에서 읽어요. 시험을 싣는 길은 두 가지예요. 앱 묶음과 웹 빌드에 넣는 시험은 src/exams 아래에 파일을 만들고 src/exams/index.ts 의 목록에 한 줄을 더해요(2장). 시험 날 단계마다 바뀌는 시험은 앱을 새로 내지 않고, exam-data/src 아래에 두고 발행 도구(`npm run exams:*`)로 검사하고 서명해서 내요(3장). 시행일(examDate)을 적으면 시험 목록에서 최근 날짜가 위로 와요.

## 1. 시험 JSON 작성법

```json
{
  "id": "exam-id",
  "title": "형식 예시 시험",
  "note": "1~21번 5지선다, 22~30번 단답형",
  "examDate": "2030-01-02",
  "isSample": false,
  "isPast": false,
  "answerReleased": false,
  "rev": 1,
  "items": [
    { "no": 1, "kind": "mc", "choices": 5, "points": 2, "typeId": "t01" },
    { "no": 22, "kind": "short", "points": 3, "typeId": "t07" }
  ],
  "types": {
    "t01": { "name": "지수와 로그" },
    "t07": { "name": "경우의 수" }
  }
}
```

위 JSON은 형식 예시예요. 제목, 시행일, 배점, 유형 모두 실제 시험의 값이 아니에요.

| 칸 | 뜻 |
| --- | --- |
| id | 시험을 가리키는 고유한 값. 기록이 이 값으로 시험을 찾으니 한 번 정하면 바꾸지 않아요. 발행 도구로 내는 시험은 영어 소문자와 숫자를 붙임표(-)로 이은 모양이고(형식 예시: exam-id), 파일 이름도 `<id>.json` 이에요 |
| title | 화면에 보이는 시험 이름 |
| note | 시험 선택 목록에 보이는 한 줄 설명 |
| examDate | 시행일("YYYY-MM-DD"). 없어도 돼요. 있으면 시험 목록에서 최근 날짜가 위로 오고 "2030년 1월 2일 시행"처럼 보여요. 실제로 있는 날짜만 받아요(2027-02-29 같은 값은 시험이 목록에서 빠져요). 시행일을 모르면 지어내지 말고 칸을 빼요 |
| isSample | 예시 데이터면 true. 화면에 "예시" 배지가 붙어요. 실제 시험은 false |
| isPast | 지난 시험(기출)이면 true. 시험을 고를 때 "이 시험지, 전에 풀어 본 적 있나요?"를 한 번 더 물어요 |
| answerReleased | 정답이 공개됐으면 true. false면 채점 대신 답을 저장해 둬요. 정답을 공개한 판을 발행한 뒤에는 false 로 돌릴 수 없어요 |
| rev | 판 번호. 1 이상의 정수이고 없으면 1로 봐요. 같은 id 의 시험을 고쳐 낼 때마다 1씩 올려요. 발행 도구로 내는 시험은 꼭 적어요(처음은 1). 앱은 묶음 안 시험과 넘겨받은 시험의 id 가 같으면 rev 가 큰 쪽을 써요(같으면 넘겨받은 쪽) |
| answersRev | 정답 판 번호. 1 이상의 정수이고 없으면 1로 봐요. 채점에 영향을 주는 값(문항의 answer, altAnswers, allCorrect, points)을 정답 공개 뒤에 고칠 때만 1 올려요. 처음 정답을 공개할 때는 올리지 않아요. 앱은 채점한 기록에 그때의 answersRev 와 점수를 남겨 두고, 더 큰 answersRev 의 판을 받으면 지금 정답으로 다시 채점하고 정정 알림을 보여 줘요 |
| answersNote | 정답 정정 안내. 학생에게 그대로 보이는 한 문장이에요. answersRev 가 2 이상이면 꼭 있어야 해요. 학생이 "정답 보기"를 누르기 전에 보는 문장이라 정답 값을 쓰지 않고 문항 번호만 적어요(형식 예시: "12번 정답이 정정됐어요.") |
| items | 문항 목록. 번호가 작은 것부터 적어요 |
| items의 no | 문항 번호 |
| items의 kind | mc(5지선다) 또는 short(단답형, 0~999 정수) |
| items의 choices | 5지선다의 보기 수. 적지 않으면 5. 찍기 운 평균은 이 값으로 계산해요(찍음 표시 문항마다 인정하는 답의 수 나누기 보기 수). 보기 수가 5가 아닌 시험의 화면(키패드 배치 등)은 아직 확인하지 않았어요 |
| items의 points | 배점 |
| items의 answer | 정답. 5지선다는 1부터 보기 수까지, 단답형은 0~999. 정답 공개 전에는 적지 않아요. 모두 정답 처리(allCorrect) 문항은 없어도 돼요 |
| items의 altAnswers | answer 말고도 정답으로 인정하는 답의 배열(복수 정답). 범위는 answer 와 같아요. answer 와 겹치거나 서로 겹치면 안 되고, answer 없이 쓸 수 없어요. 다른 정답이 없으면 칸을 빼요(빈 배열은 오류). 정답을 보여 주는 자리에는 "정답 3, 5"(형식 예시)처럼 인정하는 답이 모두 나오고 "둘 다 정답으로 인정해요."(셋 이상이면 "모두 정답으로 인정해요.")가 붙어요 |
| items의 allCorrect | 모두 정답 처리. true 만 써요. 넣은 답이 무엇이든, "안 풂"이어도 맞은 것으로 채점하고, 오답 원인 화면에 "이 문항은 모두 정답으로 처리됐어요."가 나와요. 점수 분석에서는 표시가 없는 정답으로 다뤄서 찍음 표시가 있어도 찍기 운 계산에 넣지 않아요(학생이 붙인 표시는 지우지 않아요) |
| items의 typeId | 유형. types에 있는 값이어야 해요 |
| cuts | 등급컷. 자료가 없으면 이 칸을 통째로 빼요 |
| cuts의 source | 출처. 배지("추정"이나 "확정")를 누르면 보여요 |
| cuts의 asOf | 기준. 날짜("YYYY-MM-DD")나 한국 시간의 날짜와 시각("YYYY-MM-DDTHH:mm". 시와 분은 두 자리, 시는 0~23, 분은 0~59)으로 적어요(형식 예시: 2030-01-02, 2030-01-02T20:10). 실제로 있는 날짜와 시각이어야 해요. 배지를 누르면 시각이 있을 때는 "기준: 2030년 1월 2일 오후 8시 10분"(분이 0이면 "오후 8시"), 날짜만일 때는 "기준일: 2030-01-02"처럼 보여요 |
| cuts의 confirmed | 주관 기관이 원점수 등급컷을 직접 발표했을 때만 true 예요. 학원이나 업체의 추정과 성적 발표 뒤에 업체가 계산한 값은 모두 false 예요. true 면 "확정" 배지, false 면 "추정" 배지가 붙어요 |
| cuts의 grades | 등급별 [낮은 값, 높은 값]. confirmed 가 true 면 발표한 값으로 두 값을 같게 적어요. 추정이면 여러 기관 추정치의 가장 낮은 값과 가장 높은 값을 적고, 값이 하나뿐이면 두 값을 같게 적어요("2등급 컷 82점"처럼 한 숫자로 보이고 배지는 "추정"). 값은 0점부터 만점까지이고, 높은 등급의 컷이 낮은 등급의 컷보다 낮으면 안 돼요. 여기 적은 등급만 화면에 나와요 |
| types | 유형 목록. 이름은 교육과정 단원 수준으로 적어요 |
| types의 coords | 비슷한 문항 좌표 목록. 없으면 빼요 |
| typesReady | 유형 분류가 끝났는지(true 나 false). 없으면 끝난 것으로 봐요. 정답보다 유형 분류가 늦으면 false 로 두고, types 에는 자리만 채우는 유형 하나(형식 예시: "t00": { "name": "분류 중" })를 두고 모든 문항이 그것을 가리키게 해요. false 인 동안 계단 화면과 계단으로 가는 버튼 자리에는 계단 대신 "유형 분류를 준비하고 있어요. 점수와 등급컷은 지금 볼 수 있어요."가 나오고(등급컷 자료가 없으면 "유형 분류를 준비하고 있어요. 점수는 지금 볼 수 있어요."), 유형 이름은 어디에도 나오지 않아요. 채점, 점수 해부, 오답 원인, 정답 보기는 그대로예요 |

새 칸(rev, answersRev, answersNote, typesReady, altAnswers, allCorrect, 시각이 든 asOf)은 모두 선택 칸이에요(작업 지시서 3). 칸이 없는 지금의 시험 파일도 그대로 통과하고 화면도 그대로예요. 새 칸에 null 을 적으면 오류예요(칸을 빼요). 풀이 잠금 달력은 시험 파일과 따로 두는 파일이에요(5장).

지킬 것:

- 문제 원문과 그림은 싣지 않아요. 문항은 번호로만 가리켜요.
- 실제 정답과 등급컷은 공개된 자료를 그대로 옮기고, 출처를 cuts의 source에 적어요. 지어낸 값은 넣지 않아요. 다른 기관의 자료를 쓰는 근거는 docs/자료_이용_근거.md 에 적어요.
- 추정 등급컷은 confirmed를 false로 두고, 여러 기관 추정치의 가장 낮은 값과 가장 높은 값을 범위로 적어요. 앱이 등급컷을 스스로 예측하지 않아요. 표본에서 나온 값이면 source에 표본 수를 함께 적어요(예: "응시자 812명 가운데 자기 채점 입력").
- 시험 파일의 글자는 학생 화면에 그대로 나와요. 금지 문자(줄표, 가운뎃점), 느낌표, 이모지를 쓰지 않아요(발행 도구는 거부해요).

## 2. 시험 등록

앱 묶음과 웹 빌드에 넣는 시험이에요. src/exams 에 파일(형식 예시: exam-id.json)을 두고 src/exams/index.ts 에 두 줄을 더해요.

```ts
import rawExam from './exam-id.json';

const RAW: unknown[] = [rawExam, rawA, rawB, rawC];
```

화면의 시험 목록 순서는 이렇게 정해져요(src/exams/merge.ts 의 sortExams, src/exams/index.ts 가 다시 내보내요). 아이폰 앱 껍데기가 넘겨준 시험(다리 규격 2)도 같은 규칙으로 놓이고, 시행일이 없는 넘겨받은 시험은 예시 시험보다 위에 와요.

1. examDate가 있는 시험이 먼저 오고, 최근 날짜가 위예요.
2. 날짜가 같은 시험은 위 배열(RAW)의 순서를 따라요.
3. examDate가 없는 시험은 그 아래에 배열 순서대로 와요(예시 시험 A, B, C는 시행일이 없어서 이 자리예요).

날짜는 Date로 바꾸지 않고 문자열을 연, 월, 일로 잘라 검사하고 정렬하고 화면에 적어요. 그래서 앱을 여는 기기의 시간대와 상관없이 같은 날짜가 나와요.

그다음 검사를 돌려요.

```bash
npm test
```

src/logic/scoring.test.ts 의 "예시 시험 3개가 모두 검사를 통과한다" 테스트는 시험 id 목록을 그대로 견줘요. 시험을 더했으면 그 목록에 새 id를 맨 앞에 더해요. 이 테스트가 목록의 모든 시험 파일을 검사하므로, 깨진 파일을 올리는 일을 막아 줘요.
좌표 라벨이 "예시 좌표"인지 보는 테스트는 예시 시험(isSample 이 true)만 봐요. 실제 시험에는 아래 4번 형식의 실제 표기를 넣어도 테스트가 통과해요.

정답이 든 시험이면 `npm run dev` 로 열어 정답 그대로 모든 문항을 넣었을 때 만점이 나오는지 직접 확인해요. 묶음 안 시험을 바꿨으면 `npm run build` 뒤 dist 폴더를 올리고, 앱 묶음은 소스를 커밋한 뒤 `npm run build:app` 으로 다시 만들어 커밋해요(앱은 새로 내야 바뀌어요).

잘못된 값(없는 유형, 범위를 벗어난 정답, 확정인데 두 값이 다른 컷 등)이 있는 시험은 앱에서 목록에서 빠지고 브라우저 콘솔에 이유가 나와요. 넘겨받은 시험도 같은 검사로 걸러요. 검사 규칙은 src/exams/validate.ts 의 validateExam 에 있어요.

발행 도구로 내는 시험(3장)은 여기에 등록하지 않아요. 같은 시험을 묶음에도 넣으면 앱은 id 가 같은 두 판 가운데 rev 가 큰 쪽을 써요(같으면 넘겨받은 쪽).

## 3. 시험 당일 절차

시험 날에는 단계마다 앱을 새로 빌드하거나 새로 내지 않아요. 원본 시험 파일을 고치고 발행 도구로 검사하고 서명해서 정해진 주소 한 곳에 올리면, 아이폰 앱 껍데기가 받아 서명과 SHA-256 을 확인한 뒤 웹에 넘겨요(다리 규격 2, 작업 지시서 4). 사람이 따라 하는 순서(전날 점검, 단계마다 칠 명령과 확인할 출력, 두 사람 확인, 고쳐 내는 법, 리허설)는 docs/시험_당일_순서.md, 발행물의 형식과 받는 쪽 규칙은 docs/시험_배포_규격.md 에 있어요. 브라우저에서 여는 웹 빌드(dist, 단일 HTML)는 스스로 통신하지 않아서 묶음 안 시험(2장)만 보여요.

### 3-1. 발행 도구로 가는 길

1. 원본 시험 파일을 exam-data/src/<시험 id>.json 에 둬요. 1장의 형식이고 rev 를 꼭 적어요(처음은 1). 이 폴더는 처음에 비어 있어요(자리 파일 README.md 만 있어요).
2. `npm run exams:check` 로 검사해요. src/exams/validate.ts 의 검사(앱과 같은 규칙), 발행 도구만의 규칙(파일 이름, id 모양, rev, 화면 글자의 금지 문자와 느낌표와 이모지), 마지막 발행 기록(exam-data/state.json)과 견준 금지된 변경을 보고 변경 요약을 보여 줘요. 아무것도 쓰지 않아요.
3. 비밀 키를 환경 변수 SA_EXAM_KEY_FILE 로 가리키고(저장소 밖 파일) `npm run exams:publish` 로 발행해요. seq 를 올려 dist-exams 에 발행물을 새로 만들고 서명하고 state.json 을 고쳐요.
4. `npm run exams:verify` 로 발행 폴더를 확인하고, 정해진 주소에 올린 뒤 `npm run exams:verify -- https://<정해진 주소>/` 로 한 번 더 확인해요. exam-data 의 바뀐 것(src, locks.json, state.json)은 커밋해요.

정답 넣기(`npm run exams:answers`)와 추정 등급컷 넣기(`npm run exams:cuts`)는 도구가 원본을 고쳐 줘요. 두 명령은 원본이 발행한 판과 달라지면 rev 도 올려 줘요. 그 밖의 단계(유형 분류, 주관 기관이 발표한 컷, 배점 정정)는 원본을 손으로 고치고 rev 를 1 올려요.

### 3-2. 단계와 화면

시험 날의 상태는 아래 차례로 바뀌어요. 단계마다 원본을 고친 뒤 3-1의 2~4를 해요.

| 때 | 원본에서 할 일 | 화면 |
| --- | --- | --- |
| 시험 전이나 직후(정답 공개 전) | 원본을 만들어요. answerReleased 는 false. items에 answer를 적지 않아요. cuts는 빼요. 유형 분류가 아직이면 typesReady 를 false 로 두고 자리만 채우는 유형 하나를 둬요 | 답을 넣으면 저장해 두고 "정답이 아직 공개되지 않았어요"를 보여 줘요 |
| 정답 공개 | 두 사람이 따로 적은 정답 파일로 `npm run exams:answers -- <정답 파일 1> <정답 파일 2>`. 두 파일이 같을 때만 answer(복수 정답은 altAnswers, 모두 정답 처리는 allCorrect)를 넣고 answerReleased 를 true로 해요 | 저장해 둔 답을 열면 바로 채점할 수 있어요(앱을 다시 켜지 않아도 돼요). 등급컷 상자에는 "등급컷 자료를 기다리고 있어요". typesReady 가 false 면 계단 자리에 "유형 분류를 준비하고 있어요. 점수는 지금 볼 수 있어요." |
| 유형 분류 | 문항마다 typeId 를 실제 유형으로 적고 typesReady 를 빼거나 true로, rev 를 1 올려요 | 계단("고칠 것 N가지 보기")이 나와요 |
| 추정 등급컷이 나옴 | 기관별 추정 컷 파일로 `npm run exams:cuts -- <파일>`. confirmed 는 false, grades는 여러 기관 추정치의 가장 낮은 값과 가장 높은 값(기관이 한 곳이면 두 값이 같게), source에 기관 이름, asOf에 그 값의 기준 시각이 들어가요 | "2등급 컷 81~85점"처럼 범위와 "추정" 배지. 두 값이 같으면 "2등급 컷 82점"처럼 한 숫자와 "추정" 배지 |
| 새 추정이 나옴(성적 발표 뒤에 업체가 계산한 값도) | 더 늦은 기준 시각의 파일로 `npm run exams:cuts` 를 다시 돌려요. confirmed 는 false 그대로예요 | 모양은 위와 같아요. 실제 점수가 추정 컷 범위 안이거나 컷과 같은 학생에게는 "컷 자료가 바뀌면 이 화면도 바뀌어요."가 함께 보여요 |
| 주관 기관이 원점수 등급컷을 직접 발표함 | 원본을 손으로 고쳐요. confirmed 를 true로, grades의 두 값을 발표한 값으로 같게, source에 발표한 기관, asOf를 발표 시각으로, rev 를 1 올려요 | "2등급 컷 82점"처럼 한 숫자와 "확정" 배지 |
| 정답 정정(정답 공개 뒤) | 두 사람이 고친 정답 파일로 `npm run exams:answers -- <정답 파일 1> <정답 파일 2> --note "<정정 안내>"`. answersRev 가 1 오르고 answersNote 가 들어가요 | 채점한 기록을 열면 지금 정답으로 다시 채점하고 "정답이 정정돼서 다시 채점했어요. 76점에서 79점으로 바뀌었어요."(형식 예시)와 정정 안내를 보여 줘요. 학생이 넣은 답과 표시는 바뀌지 않아요 |

배지를 누르면 출처, 기준, 설명이 나와요. 설명은 주관 기관이 발표한 컷이면 "주관 기관이 발표한 컷이에요.", 추정 범위면 "추정한 컷이라 범위로 적었어요. 새 자료가 나오면 고쳐요.", 두 값이 같은 추정이면 "추정한 컷이에요. 새 자료가 나오면 고쳐요."예요. 주관 기관이 원점수 등급컷을 발표하지 않는 시험은 끝까지 추정으로 둬요.

정답을 넣은 뒤 확인할 것:

1. 정답을 두 사람이 따로 옮겨 적어요. exams:answers 는 두 파일이 완전히 같을 때만 넣어요. 한 글자만 틀려도 그 문항을 맞힌 학생이 모두 틀린 것으로 나와요.
2. `npm run exams:check` 의 변경 요약(정답 공개, 정정한 문항 번호, 정정 안내 문장)을 두 사람이 함께 읽어요.
3. 발행한 뒤 `npm run exams:verify` 로 발행 폴더와 올린 주소를 확인해요.

알아 둘 것:

- 발행물은 정해진 주소에 올리는 파일이라 누구나 받을 수 있어요. 화면에는 "정답 보기"를 누르기 전까지 정답이 나오지 않지만, 파일을 열면 볼 수 있어요. 그래서 정답 공개 전에는 answer를 아예 싣지 않아요(exams:check 가 알려요). 묶음 안 시험도 정답이 앱 파일 안에 들어가서 같아요.
- 학생의 기록은 id로 시험을 찾아요. 발행한 시험은 지울 수 없고, 문항 구성(no, kind, choices)도 바꿀 수 없어요(발행 도구가 거부해요).
- 정답을 고쳐 내면(answersRev 를 올린 판) 그 뒤에 여는 기록은 고친 정답으로 다시 채점되고 정정 알림이 나와요.
- 낸 것을 되돌리는 방법은 없어요. 고쳐서 rev 를 올려 다시 내요(docs/시험_당일_순서.md 6장).

## 4. 좌표 표기 규칙

좌표는 "이 유형의 비슷한 문항이 어느 시험 몇 번에 있는지"를 가리키는 말이에요. 문제 내용은 싣지 않고 위치만 적어요.

```json
"t06": {
  "name": "적분",
  "coords": [
    { "label": "2025학년도 6월 모의평가(2024년 6월 시행)", "itemNo": 14 }
  ]
}
```

- 위는 형식만 보여 주는 예시예요. 그 번호에 그 유형의 문항이 있는지 확인한 좌표가 아니에요.
- label에는 학년도와 시행 연도를 함께 적어요. 화면에는 "2025학년도 6월 모의평가(2024년 6월 시행) 14번"처럼 label 뒤에 번호가 붙어 나와요.
- 수능과 모의평가는 학년도와 시행 연도가 한 해 어긋나서(2025학년도 수능은 2024년 11월 시행) 둘 다 적지 않으면 학생이 다른 시험지를 찾게 돼요.
- 학력평가처럼 시행 연도로 부르는 시험도 같은 형식으로 적어요(예: "2026년 3월 학력평가(고2, 2026년 3월 시행)").
- 실제로 그 번호에 그 유형의 문항이 있는지 시험지를 보고 확인한 좌표만 넣어요. 확인하지 않은 좌표는 넣지 않아요.
- 예시 데이터에는 "예시 좌표"라는 라벨의 가짜 좌표만 들어 있어요. 화면에도 "예시 좌표" 배지가 붙어요. 실제 기출을 가리키는 것이 아니에요.

## 5. 풀이 잠금 달력

수능, 평가원 모의평가, 전국연합학력평가가 치러지는 시간(일반 수험생 기준 1교시 시작부터 마지막 교시 종료까지, 한국 시간)에는 풀이 계열 기능(해설 보기, 풀이 단계 보기, 풀이 사진 판독과 평가)을 보여 주지 않아요(작업 지시서 3의 4-5). 지금 앱에는 풀이 계열 기능이 없고, 진행자용 화면에 "풀이 잠금: 지금 열림" 또는 "풀이 잠금: 지금 잠김(오후 5시 45분까지)"(형식 예시) 한 줄만 나와요. 앞으로 풀이 계열 기능을 더하는 작업은 반드시 이 판정을 거쳐요(docs/결정기록.md 6장).

달력은 항목의 배열이에요.

```json
[
  {
    "id": "exam-id-lock",
    "label": "형식 예시 시험의 1교시 시작부터 마지막 교시 종료까지",
    "start": "2030-01-02T08:40",
    "end": "2030-01-02T17:45"
  }
]
```

위 JSON은 형식 예시예요. 실제 날짜와 시각은 주관 기관의 공고를 확인한 사람이 넣어요. 지어내지 않아요.

| 칸 | 뜻 |
| --- | --- |
| id | 항목 이름. 빈칸뿐이 아닌 글자이고 한 달력 안에서 겹치지 않아요. 묶음 안 달력과 넘겨받은 달력에 같은 id 가 있으면 넘겨받은 항목을 써요 |
| label | 사람이 보는 메모. 화면에 쓰지 않지만 비우지 않아요 |
| start | 잠그기 시작하는 시각. "YYYY-MM-DDTHH:mm"(한국 시간, 두 자리, 시는 0~23, 분은 0~59) |
| end | 푸는 시각. start 와 같은 날이고 start 보다 늦어요. 잠기는 구간은 start 이상 end 미만이에요 |

- 달력은 두 곳에 있어요. 앱 묶음 안 달력 src/exams/locks.json 은 앱을 새로 내야 바뀌어요. 발행하는 달력 exam-data/locks.json 은 발행할 때 index.json 의 locks 로 나가요. 둘 다 지금은 빈 배열이에요. 앱은 두 달력을 id 로 합치고, 시험 날 쓰는 것은 exam-data/locks.json 이에요(docs/시험_당일_순서.md 7장).
- 판정은 한국 시간을 UTC 보다 9시간 빠른 것으로 고정해서 하고 기기의 시간대 설정을 쓰지 않아요.
- 형식이 틀린 항목은 앱이 버리고 개발자 콘솔에 이유를 남겨요. 발행 도구(exams:check, exams:publish)는 거부해요.
