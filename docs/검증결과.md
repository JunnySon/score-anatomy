## 6. 외부 요청

글꼴(Pretendard dynamic subset)과 스크립트는 프로젝트 안에 실려 있어요.

아티팩트용 파일(335 KB)도 뼈대에 넣어 열었을 때 파일 자신 말고는 요청이 없었어요(밖으로 0건). 실제 뷰어 안에서는 확인하지 못했어요.

## 9. 정답 노출

두 가지 방법으로 봤어요.

첫째, 차분 검사(e2e/leak.spec.ts). 배포하는 빌드와, 검산 예시에서 틀리는 6문항(11, 15, 20, 21, 27, 29번)의 정답만 다른 값으로 바꾼 검증용 빌드에 똑같은 조작을 했어요.
화면마다 보이는 글자, 숨은 글자, 모든 속성, 입력 칸 값, 가상 요소 글자를 통째로 견줘서, 한 글자라도 다르면 정답이 드러난 것으로 봐요.
"정답 보기"를 누르기 전의 화면 25곳을 견줬고 다른 곳은 0곳이에요.
대조: "정답 보기"를 누른 뒤에는 두 빌드의 화면이 달라졌어요(단답형 27번 달라짐, 5지선다 15번 달라짐). 이 검사가 노출을 실제로 잡아낸다는 뜻이에요.

둘째, 화면을 읽는 검사(e2e/audit.ts 의 findAnswerLeaks). 화면 글자, 입력칸 안내문과 값, 접근성 라벨, 그 밖의 속성에 틀린 문항의 정답이 나오는지 봤어요.
