# 점수 해부 (시제품 1.1, 버전 0.3.0)

종이로 친 수능 수학 모의고사의 답 30개를 폰에서 터치로 넣으면, 채점해서 점수를 나눠 보여 주고(점수 해부) 먼저 고칠 것 2~3개(계단)를 알려 주는 모바일 웹앱 시제품이에요.

- 백엔드가 없는 정적 웹앱이에요. 가입과 로그인이 없고, 기록은 이 기기의 브라우저 저장소에만 남아요.
- 웹 코드는 실행 중 외부 네트워크 요청을 하지 않아요. 글꼴과 스크립트를 프로젝트 안에 실었어요. 아이폰 앱에서는 껍데기가 정해진 주소 한 곳에서 시험 자료를 받기만 해요(작업 지시서 4).
- 들어 있는 시험 3개는 모두 예시 데이터예요. 실제 기출 문제, 정답, 등급컷은 들어 있지 않아요.
- 용도는 고2 8~10명 사용성 테스트예요. 진행 방법은 docs/사용성테스트_진행안내.md 에 있어요.
- 1.1에서 바뀐 것(키패드의 잠금과 지우기, 채점 버튼 하나, 보기 수로 계산하는 찍기 운 평균, 찍음 표시 정답의 스스로 확인, 시험 시행일, 버린 누름 알림, 테스트 기기의 기록 탭 등 11가지)은 docs/결정기록.md 4장에 있어요.
- 0.3.0(작업 지시서 3, 시험 당일 경로)에서 시험 날 정답과 등급컷을 앱을 새로 내지 않고 넣는 길을 만들었어요. 시험 파일의 새 칸(판 번호, 정답 정정, 복수 정답, 모두 정답 처리, 유형 분류 전, 기준 시각이 든 등급컷), 정답 정정 알림, 풀이 잠금 판정, 아이폰 앱 껍데기가 넘겨주는 시험 자료 받기(다리 규격 2), 시험 자료 발행 도구(exam-data, `npm run exams:*`)예요. 정한 것은 docs/결정기록.md 6장에 있어요.

## 실행 방법

Node.js 22 버전대(22.12 이상), 24 버전대, 26 이상 가운데 하나가 필요해요. 단위 테스트 도구(Vitest 5)가 20, 21, 23, 25 버전대를 지원 범위에 두지 않아요. 개발 서버와 빌드만 쓴다면 20 버전대(20.19 이상)와 23, 25 버전대에서도 돼요(Vite 8 기준). 시험 자료 발행 도구(`npm run exams:*`)는 Node 가 TypeScript 파일을 바로 읽는 기능을 써서 22.18 이상이 필요해요.

```bash
npm install
```

```bash
npm run dev
```

터미널에 나오는 주소(보통 http://localhost:5173)를 브라우저로 열어요.
크롬 개발자 도구의 기기 모드에서 폭 360~430px로 보면 폰 화면과 같아요.

## 빌드 방법

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm run build` | 타입 검사 뒤 dist 폴더에 정적 산출물을 만들어요 |
| `npm run build:single` | 모든 자산을 넣은 HTML 파일 1개를 dist-single/index.html 로 만들어요(시스템 글꼴만 사용) |
| `npm test` | 단위 테스트(Vitest). 발행 도구(scripts/exams)의 테스트도 함께 돌아요 |
| `npm run e2e` | 빌드 뒤 화면 흐름 테스트(Playwright). 앱용 묶음 테스트는 커밋된 묶음(ios/ScoreAnatomy/Web)을 열어요 |
| `npm run build:app` | 아이폰 앱 껍데기에 싣는 묶음 두 가지와 manifest.json 을 ios/ScoreAnatomy/Web 에 만들어요 |
| `npm run verify` | 자동 검증 전체(13개 항목)를 돌리고 docs/검증결과.md 와 docs/screens(밝은 화면, 어두운 화면, 작은 화면 79장씩)를 새로 써요 |

dist 폴더는 상대 경로와 해시 라우팅을 쓰기 때문에 어떤 정적 호스팅의 어떤 하위 경로에 올려도 열려요. 서비스 워커는 없어요.

보조 명령도 있어요.

| 명령 | 하는 일 |
| --- | --- |
| `npm run preview` | dist 폴더를 미리 보기 |
| `npm run build:variant` | 검증에만 쓰는 변형 빌드를 verify-out/dist-variant 에 만들어요. 예시 시험 A에서 틀리는 6문항의 정답만 다르고, 예시 시험 B에는 등급컷이 없어요. 배포하지 않아요 |
| `npm run build:artifact` | 단일 HTML을 아티팩트 뷰어용 파일(release/score-anatomy-artifact.html)로 바꿔요 |
| `npm run package` | 전달용 파일을 release 폴더에 모아요(단일 HTML 사본, 아티팩트용 파일, 프로젝트 압축 파일) |

verify 의 13개 항목은 docs/작업지시서.md 10장의 10개(단위 테스트, 화면 흐름, 작은 화면, 글자 크기, 터치 영역, 외부 요청, 금지 문자, 색 대비, 정답 노출, 화면 캡처), 작업 지시서 1의 앱용 묶음 2개(11번 다시 만든 묶음과 같은지, 12번 가짜 다리를 넣은 브라우저에서 두 묶음 검사), 작업 지시서 3의 발행 도구 1개(13번)예요.

화면 테스트(`npm run e2e`, `npm run verify`)는 4173, 4174 포트에 미리 보기 서버를 새로 띄워요. 그 포트를 이미 쓰고 있으면(예: `npm run preview` 가 떠 있을 때) 옛 빌드를 재지 않으려고 실패로 끝나요. 떠 있는 서버를 내리거나 다른 포트를 주세요.

```bash
SA_PORT=4300 npm run verify
```

verify 는 리눅스, 맥, 윈도우에서 돌아요. 윈도우에서는 받은 저장소의 줄바꿈을 .gitattributes 가 LF로 맞춰요(1.1).

화면 테스트는 Playwright의 Chromium을 써요. 처음이면 브라우저를 한 번 내려받아요.

```bash
npx playwright install chromium
```

내려받을 수 없는 환경이면 시스템에 설치된 크롬을 쓰게 할 수 있어요.

```bash
SA_BROWSER_CHANNEL=chrome npm run verify
```

실행 파일을 직접 가리킬 수도 있어요.

```bash
SA_CHROMIUM_PATH=/usr/bin/chromium npm run verify
```

## 폰에서 여는 방법

세 가지 방법이 있어요. 실제 아이폰과 안드로이드 기기에서는 아직 확인하지 못했어요.

1. 같은 와이파이에서 열기
   컴퓨터에서 `npm run dev` 를 실행하면 터미널에 Network 주소(예: http://192.168.0.12:5173)가 나와요. 폰 브라우저에 그 주소를 넣어요. 컴퓨터와 폰이 같은 와이파이에 있어야 해요.

2. 파일 하나로 열기
   `npm run build:single` 로 만든 dist-single/index.html 파일 하나를 폰으로 보내 브라우저(Chrome, Safari)로 열어요. 인터넷이 없어도 돼요. `npm run package` 를 실행하면 같은 파일이 release/score-anatomy.html 로도 생겨요.
   메신저나 파일 앱의 미리보기로 열면 스크립트가 돌지 않을 수 있어요. 그럴 때는 브라우저로 여는 메뉴를 고르거나 아래 3번 방법을 써요.
   파일로 열면 브라우저에 따라 기록 저장이 안 될 수 있어요. 그래도 화면은 그대로 동작해요.

3. 정적 호스팅에 올려 주소로 열기
   `npm run build` 로 만든 dist 폴더를 통째로 정적 호스팅에 올리고 그 주소를 폰으로 열어요. 사용성 테스트처럼 여러 기기에서 쓸 때 가장 확실한 방법이에요.

입력 방식은 주소로 바꿀 수 있어요. 주소 끝에 `#/?input=rows`(5행 방식)나 `#/?input=keypad`(키패드 방식, 기본)를 붙여요.
테스트 진행자용 화면은 주소 끝에 `#/test` 를 붙이거나 기록 화면 맨 아래 링크로 들어가요.

## 아이폰 앱용 묶음

아이폰 앱은 화면 전체를 차지하는 웹뷰 하나에 이 웹 코드를 싣는 얇은 껍데기예요. 이 저장소는 껍데기에 실을 묶음 두 가지를 만들어 커밋해요(맥에서는 Node 없이 이 파일만 써요).

```bash
npm run build:app
```

| 파일 | 뜻 |
| --- | --- |
| ios/ScoreAnatomy/Web/app-test/index.html | 시험용 묶음. 진행자용 화면과 입력 방식 전환을 포함해요(아이폰에서 사용성 테스트를 할 때, Debug 빌드) |
| ios/ScoreAnatomy/Web/app-release/index.html | 배포용 묶음. 진행자용 화면과 그리로 가는 링크, 입력 방식 전환과 5행 방식 화면, "준비 중인 기능" 목록이 코드와 글자에서 빠져 있어요. 그 화면들만 쓰는 모양(CSS)과 사용성 테스트 측정 기록 코드도 빠져 있어요(Release 빌드) |
| ios/ScoreAnatomy/Web/manifest.json | 묶음을 만든 때의 커밋(과 그때 커밋하지 않은 바뀜이 있었는지), 버전(0.3.0), 다리 규격 번호(bridge 는 이 묶음이 돌아가는 가장 낮은 규격 1, bridgeMax 는 웹이 아는 가장 높은 규격 2), 파일별 SHA-256 |

- 둘 다 시스템 글꼴을 쓰는 단일 HTML이고 외부 요청이 없어요.
- 껍데기와 주고받는 약속은 docs/앱_다리_규격.md 에 있어요. 규격 1은 저장, 햅틱, 복사, 글자 크기이고, 규격 2는 껍데기가 정해진 주소에서 받아 확인한 시험 자료를 웹에 넘겨주는 것(remote, remoteFailed, saRemote)이에요. 웹은 규격 1과 2를 받아요. 묶음을 브라우저로 열면(window.__SA_APP__ 와 다리가 없으면) 브라우저 방식(localStorage, 브라우저 복사, 브라우저 문구)으로 동작하고 묶음 안 시험만 써요. 배포용 묶음은 이때도 진행자용 화면, 5행 방식, "준비 중인 기능" 목록이 없어요.
- 규격 2 껍데기가 시험 자료를 넘겨주면 시험 선택 화면 아래에 받은 자료 안내("시험 자료는 정해진 주소 한 곳에서 받아요. 넣은 답과 기록은 보내지 않아요."와 받은 자료 기준 시각)와 "새로 확인" 버튼이 나와요. 규격 1 껍데기, 브라우저, 넘겨받은 자료가 없을 때는 이 안내와 버튼이 나오지 않아요. 웹은 스스로 통신하지 않아요.
- 소스를 고쳤으면 먼저 커밋한 뒤 `npm run build:app` 을 돌려 세 파일을 함께 커밋해요. 화면 테스트(`npm run e2e`)의 앱용 묶음 테스트는 커밋된 묶음을 열므로, 소스를 고친 뒤에는 먼저 `npm run build:app` 을 돌려요. `npm run verify` 가 지금 코드로 묶음을 다시 만들어 HEAD 에 커밋된 묶음과 같은지, manifest 의 커밋이 묶음을 만든 코드를 가리키는지(11번), 가짜 다리를 넣은 브라우저에서 두 묶음이 동작하는지(12번, 규격 2의 넘겨받기 포함) 확인해요. Playwright 의 WebKit 이 설치돼 있으면(`npx playwright install webkit`) 앱 시험용 묶음의 흐름을 WebKit 으로도 한 번 돌려요.
- 아이폰 앱 껍데기(Xcode 프로젝트)는 작업 지시서 2에서 맥으로 만들어요. 껍데기가 정해진 주소에서 발행물을 받아 서명과 SHA-256 을 확인하고 웹에 넘기는 일은 작업 지시서 4예요.

## 시험 자료 발행

시험 날 정답과 등급컷은 앱을 새로 내지 않고 발행물로 내요. 팀이 exam-data 의 원본을 고치고 발행 도구로 검사하고 서명해서 정해진 주소 한 곳에 올리면, 아이폰 앱 껍데기가 받아 확인한 뒤 웹에 넘겨요. 주소는 아직 정하지 않았어요.

| 명령 | 하는 일 |
| --- | --- |
| `npm run exams:check` | 원본을 검사하고 마지막 발행 기록과 견줘 변경 요약을 보여 줘요. 앱 묶음에 든 시험(src/exams)과 같은 id 는 거부해요. 파일을 쓰지 않아요 |
| `npm run exams:answers -- <정답 파일 1> <정답 파일 2>` | 두 사람이 따로 적은 정답 파일이 같을 때만 원본에 정답을 넣어요 |
| `npm run exams:cuts -- <추정 컷 파일>` | 기관별 추정 컷으로 등급컷 범위를 써요 |
| `npm run exams:publish` | 검사를 통과하면 dist-exams 에 발행물을 만들고 서명해요. 비밀 키는 환경 변수 SA_EXAM_KEY_FILE 이 가리키는 저장소 밖 파일에서만 읽어요. 저장소의 exam-data 로 발행할 때는 짝인 공개 키(exam-data/public-key.txt)가 있어야 해요 |
| `npm run exams:verify` | 발행 폴더나 주소의 서명과 SHA-256 을 확인해요. 주소를 확인할 때는 자료 폴더의 마지막 발행과 다르면 실패예요 |
| `npm run exams:serve` | 발행 폴더를 이 컴퓨터에서 내줘요(리허설용, http://127.0.0.1:4180/) |
| `npm run exams:keygen -- <비밀 키 경로>` | 서명 키 쌍을 만들어요. 비밀 키는 저장소 밖에, 공개 키는 exam-data/public-key.txt 에 써요 |
| `npm run exams:testdata` | 테스트 전용 키와 발행물 네 가지를 exam-data/testdata 에 만들어요. 진짜 발행에는 쓰지 않아요 |

- exam-data/src 는 비어 있고 exam-data/locks.json 은 빈 배열이에요. 실제 시험 자료와 잠금 날짜는 주관 기관의 자료를 확인한 사람이 넣어요. 진짜 서명 키와 공개 키(exam-data/public-key.txt)도 아직 없어요(사람이 만들어요).
- 사람이 따라 하는 순서는 docs/시험_당일_순서.md, 발행물 형식과 받는 쪽 규칙은 docs/시험_배포_규격.md 에 있어요.
- `npm run verify` 의 13번이 발행 도구의 단위 테스트와 테스트 전용 발행물 네 가지를 확인해요.

## 폴더 구조

```
src/
  strings.ts        화면 문구 전부(한 파일)
  styles/tokens.css 디자인 값 전부(색, 글자, 간격)
  exams/            시험 데이터(JSON 파일 하나가 시험 하나), 시험 검사, 넘겨받은 시험 합치기, 풀이 잠금 달력
  logic/            계산 규칙: 채점, 점수 해부, 등급컷, 계단, 풀이 잠금 판정
  state/            기록 저장(브라우저는 localStorage, 앱은 다리), 사용성 테스트 측정 기록
  platform/         브라우저와 아이폰 앱에 따라 다른 것(저장, 복사, 햅틱, 앱 문구, 시험 자료 넘겨받기). app.ts 는 앱용 묶음에만 실어요
  tools/            사용성 테스트 도구(진행자용 화면, 5행 방식) 모듈. 앱 배포용 묶음은 빈 모듈(none.ts)을 실어요
  screens/          화면 12종
  components/       공통 부품(화면 틀, 키패드, 바텀시트, 점수 막대, 알림)
e2e/                화면 흐름 테스트와 화면 검사(Playwright)
scripts/            검증 스크립트, 단일 HTML 빌드, 앱용 묶음 빌드, 전달용 파일 묶기, 시험 자료 발행 도구(exams.mjs, exams/)
exam-data/          발행할 시험 원본(src), 풀이 잠금 달력(locks.json), 마지막 발행 기록(state.json), 테스트 전용 발행물(testdata)
ios/ScoreAnatomy/Web/ 앱용 묶음 두 가지와 manifest.json(커밋해요)
docs/               문서와 화면 캡처
```

아래 폴더는 명령을 실행하면 생기고 git에는 넣지 않아요.

```
dist/               npm run build 결과
dist-single/        npm run build:single 결과(HTML 파일 1개)
dist-exams/         npm run exams:publish 결과(발행 폴더, 정해진 주소에 올려요)
release/            npm run package 결과(전달용 파일)
verify-out/         npm run verify 가 쓰는 중간 결과와 검증용 변형 빌드
```

## 지키는 원칙

- 미성년자 보호: 연속 기록, 순위, 배지, 다른 학생과 비교, 알림 권한 요청이 없어요.
- 개인정보 최소: 이름을 받지 않아요. 서버 전송, 분석 도구, 광고가 없어요. 앱은 시험 자료를 받기만 하고 넣은 답과 기록은 보내지 않아요.
- 정직한 숫자: 실제 점수는 채점 결과 그대로예요. 추정값에는 "추정" 배지와 "약"을 붙여요. "확정" 배지는 주관 기관이 원점수 등급컷을 직접 발표했을 때만 붙이고, 등급컷을 앱이 스스로 예측하지 않아요.
- 정답 노출 금지: "정답 보기"를 누르기 전에는 정답을 보여 주지 않아요.
- 학생이 넣은 답과 표시는 어떤 경우에도 바꾸지 않아요. 정답이 정정되면 다시 채점하고 바뀐 것을 알려요.
