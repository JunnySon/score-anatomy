# 시험 추가 방법

결론: 시험 하나는 src/exams 아래 JSON 파일 하나예요. 파일을 만들고 src/exams/index.ts 의 목록 맨 앞에 한 줄을 더하면 돼요. 화면 구성(문항 수, 객관식과 단답형 배열, 배점, 등급 수)은 전부 이 파일에서 읽어요.

## 1. 시험 JSON 작성법

```json
{
  "id": "2027-03",
  "title": "2027년 3월 학력평가",
  "note": "1~21번 5지선다, 22~30번 단답형",
  "isSample": false,
  "isPast": false,
  "answerReleased": false,
  "items": [
    { "no": 1, "kind": "mc", "choices": 5, "points": 2, "typeId": "t01" },
    { "no": 22, "kind": "short", "points": 3, "typeId": "t07" }
  ],
  "types": {
    "t01": { "name": "지수와 로그" },
    "t07": { "name": "경우의 수" }
  }
}
```

위 JSON은 형식을 보여 주는 것이고 실제 시험 값이 아니에요.

| 칸 | 뜻 |
| --- | --- |
| id | 시험을 가리키는 고유한 값. 기록이 이 값으로 시험을 찾으니 한 번 정하면 바꾸지 않아요 |
| title | 화면에 보이는 시험 이름 |
| note | 시험 선택 목록에 보이는 한 줄 설명 |
| isSample | 예시 데이터면 true. 화면에 "예시" 배지가 붙어요. 실제 시험은 false |
| isPast | 지난 시험(기출)이면 true. 시험을 고를 때 "이 시험지, 전에 풀어 본 적 있나요?"를 한 번 더 물어요 |
| answerReleased | 정답이 공개됐으면 true. false면 채점 대신 답을 저장해 둬요 |
| items | 문항 목록. 번호가 작은 것부터 적어요 |
| items의 no | 문항 번호 |
| items의 kind | mc(5지선다) 또는 short(단답형, 0~999 정수) |
| items의 choices | 5지선다의 보기 수. 적지 않으면 5 |
| items의 points | 배점 |
| items의 answer | 정답. 5지선다는 1~5, 단답형은 0~999. 정답 공개 전에는 적지 않아요 |
| items의 typeId | 유형. types에 있는 값이어야 해요 |
| cuts | 등급컷. 자료가 없으면 이 칸을 통째로 빼요 |
| cuts의 source | 출처. 추정 배지를 누르면 보여요 |
| cuts의 asOf | 기준일(예: 2027-03-25) |
| cuts의 confirmed | 확정 컷이면 true |
| cuts의 grades | 등급별 [낮은 값, 높은 값]. 확정이면 두 값을 같게 적어요. 여기 적은 등급만 화면에 나와요 |
| types | 유형 목록. 이름은 교육과정 단원 수준으로 적어요 |
| types의 coords | 비슷한 문항 좌표 목록. 없으면 빼요 |

지킬 것:

- 문제 원문과 그림은 싣지 않아요. 문항은 번호로만 가리켜요.
- 실제 정답과 등급컷은 공개된 자료를 그대로 옮기고, 출처를 cuts의 source에 적어요. 지어낸 값은 넣지 않아요.
- 추정 등급컷은 범위로 적고 confirmed를 false로 둬요. 표본에서 나온 값이면 source에 표본 수를 함께 적어요(예: "응시자 812명 가운데 자기 채점 입력").

## 2. 시험 등록

src/exams/index.ts 에 두 줄을 더해요. 목록의 맨 위가 가장 최근 시험이에요.

```ts
import raw2703 from './2027-03.json';

const RAW: unknown[] = [raw2703, rawA, rawB, rawC];
```

그다음 검사를 돌려요.

```bash
npm test
```

src/logic/scoring.test.ts 의 "예시 시험 3개가 모두 검사를 통과한다" 테스트는 시험 id 목록을 그대로 견줘요. 시험을 더했으면 그 목록에 새 id를 맨 앞에 더해요. 이 테스트가 목록의 모든 시험 파일을 검사하므로, 깨진 파일을 올리는 일을 막아 줘요.

잘못된 값(없는 유형, 범위를 벗어난 정답, 확정인데 두 값이 다른 컷 등)이 있는 시험은 앱에서 목록에서 빠지고 브라우저 콘솔에 이유가 나와요. 검사 규칙은 src/exams/validate.ts 의 validateExam 에 있어요.

## 3. 시험 당일 절차

시험 날의 상태는 네 단계로 바뀌어요. 단계마다 JSON을 고치고 다시 빌드해서 올려요.

| 때 | JSON에서 할 일 | 화면 |
| --- | --- | --- |
| 시험 전이나 직후(정답 공개 전) | answerReleased 는 false. items에 answer를 적지 않아요. cuts는 빼요 | 답을 넣으면 저장해 두고 "정답이 아직 공개되지 않았어요"를 보여 줘요 |
| 정답 공개 | items마다 answer를 적고 answerReleased 를 true로 | 저장해 둔 답을 열면 바로 채점할 수 있어요. 등급컷 상자에는 "등급컷 자료를 기다리고 있어요" |
| 추정 등급컷이 나옴 | cuts를 더해요. confirmed 는 false, grades는 범위, source와 asOf를 적어요 | "2등급 컷 81~85점"처럼 범위와 "추정" 배지 |
| 등급컷 확정 | confirmed 를 true로, grades의 두 값을 같게, asOf를 확정일로 | "2등급 컷 82점"처럼 한 숫자와 "확정" 배지 |

정답을 넣은 뒤 확인할 것:

1. 정답을 두 사람이 따로 옮겨 적고 서로 맞춰 봐요. 한 글자만 틀려도 그 문항을 맞힌 학생이 모두 틀린 것으로 나와요.
2. `npm test` 로 형식 검사를 통과시켜요.
3. `npm run dev` 로 열어 정답 그대로 30개를 넣었을 때 100점이 나오는지 직접 확인해요.
4. `npm run build` 뒤 dist 폴더를 올려요.

알아 둘 것:

- 이 앱은 백엔드가 없어서 정답이 앱 파일 안에 들어가요. 화면에는 "정답 보기"를 누르기 전까지 정답이 나오지 않지만, 파일을 뜯어 보면 볼 수 있어요. 그래서 정답 공개 전에는 answer를 아예 싣지 않아요.
- 학생의 기록은 id로 시험을 찾아요. 정답을 고쳐 올리면 그 뒤에 여는 기록은 고친 정답으로 다시 채점돼요.

## 4. 좌표 표기 규칙

좌표는 "이 유형의 비슷한 문항이 어느 시험 몇 번에 있는지"를 가리키는 말이에요. 문제 내용은 싣지 않고 위치만 적어요.

```json
"t06": {
  "name": "적분",
  "coords": [
    { "label": "2025학년도 6월 모의평가(2024년 6월 시행)", "itemNo": 14 }
  ]
}
```

- label에는 학년도와 시행 연도를 함께 적어요. 화면에는 "2025학년도 6월 모의평가(2024년 6월 시행) 14번"처럼 label 뒤에 번호가 붙어 나와요.
- 수능과 모의평가는 학년도와 시행 연도가 한 해 어긋나서(2025학년도 수능은 2024년 11월 시행) 둘 다 적지 않으면 학생이 다른 시험지를 찾게 돼요.
- 학력평가처럼 시행 연도로 부르는 시험도 같은 형식으로 적어요(예: "2026년 3월 학력평가(고2, 2026년 3월 시행)").
- 실제로 그 번호에 그 유형의 문항이 있는지 시험지를 보고 확인한 좌표만 넣어요. 확인하지 않은 좌표는 넣지 않아요.
- 예시 데이터에는 "예시 좌표"라는 라벨의 가짜 좌표만 들어 있어요. 화면에도 "예시 좌표" 배지가 붙어요. 실제 기출을 가리키는 것이 아니에요.
