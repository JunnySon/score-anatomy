# 시험 당일 순서

결론: 시험 날에는 앱을 새로 내지 않고, 단계마다 원본을 고쳐 발행 도구로 발행하고 정해진 주소에 올려요. 단계는 문항 구성과 배점(정답 공개 전), 정답, 유형 분류, 추정 등급컷, 성적 발표 뒤 자료 차례예요. 단계마다 같은 일곱 걸음(원본 고치기, 검사, 발행, 발행 폴더 확인, 커밋, 올리기, 주소 확인)을 하고, 정답은 두 사람이 따로 적은 파일이 같을 때만 들어가요. 낸 것은 되돌리지 않고 rev 를 올려 다시 내요. 이 문서는 사람이 따라 하는 순서이고, 발행물의 형식과 받는 쪽 규칙은 docs/시험_배포_규격.md, 시험 파일의 칸은 docs/시험_추가_방법.md 에 있어요.

이 문서에 나오는 값(시험 id, 날짜, 시각, 문항 수, 등급컷, 지문, 기관 이름, 출력 예)은 모두 형식 예시예요. 실제 시험의 정답, 배점, 등급컷, 시행일, 시험 시간은 주관 기관의 공고와 자료를 확인한 사람만 넣어요. 다른 기관의 자료를 쓰는 근거는 docs/자료_이용_근거.md 에 적어요.

## 1. 미리 알아 둘 것

### 1-1. 사람

| 맡은 일 | 하는 일 |
| --- | --- |
| 자료 담당 두 사람 | 정답 파일을 한 사람에 하나씩 따로 적어요. 발행 전에 검사 요약을 함께 읽고, 추정 컷과 잠금 달력의 값을 서로 견줘요 |
| 키를 맡은 사람 | 비밀 키 파일을 가지고 발행(exams:publish)해요. 비밀 키는 이 사람의 컴퓨터, 저장소 밖에만 있어요 |
| 올리는 사람 | 발행 폴더를 정해진 주소에 올려요(키를 맡은 사람이 해도 돼요). 올리는 방법은 주소를 정할 때 함께 정해요 |

### 1-2. 폴더와 파일

| 경로 | 뜻 |
| --- | --- |
| exam-data/src/<시험 id>.json | 원본 시험 파일. 사람과 exams:answers, exams:cuts 가 고쳐요. 커밋해요 |
| exam-data/locks.json | 풀이 잠금 달력의 원본. 커밋해요 |
| exam-data/state.json | 마지막으로 발행한 내용의 기록. exams:publish 만 고쳐요. 손으로 고치지 않고 커밋해요 |
| exam-data/public-key.txt | 진짜 공개 키. 키를 맡은 사람이 한 번 만들어 커밋해요(아직 없어요) |
| dist-exams/ | 발행 폴더. exams:publish 가 통째로 새로 만들어요. 커밋하지 않고 정해진 주소에 올려요 |
| 저장소 밖의 비밀 키 파일 | 환경 변수 SA_EXAM_KEY_FILE 이 가리키는 파일. 저장소, exam-data, dist-exams 안에 두면 도구가 거부해요 |

### 1-3. 명령

| 명령 | 하는 일 | 쓰는 것 |
| --- | --- | --- |
| `npm run exams:check` | 원본을 검사하고 마지막 발행 기록과 견줘 변경 요약을 보여 줘요 | 없음 |
| `npm run exams:answers -- <정답 파일 1> <정답 파일 2>` | 두 파일이 같을 때만 원본에 정답을 넣어요. 정정이면 `--note "<정정 안내>"` 를 붙여요 | 원본 시험 파일 |
| `npm run exams:cuts -- <추정 컷 파일>` | 기관별 추정 컷으로 원본의 등급컷을 써요 | 원본 시험 파일 |
| `npm run exams:publish` | 검사를 통과하면 발행 폴더를 만들고 서명하고 state.json 을 고쳐요. `--dry-run` 은 쓰지 않고 결과만 보여 줘요 | 발행 폴더, state.json |
| `npm run exams:verify` | 발행 폴더나 주소의 서명과 SHA-256 을 확인해요 | 없음 |
| `npm run exams:serve` | 발행 폴더를 이 컴퓨터(127.0.0.1)에서 내줘요(리허설용) | 없음 |
| `npm run exams:keygen -- <비밀 키 경로>` | 키 쌍을 만들어요(키를 맡은 사람이 처음 한 번, 그리고 리허설) | 비밀 키, public-key.txt |

- 종료 코드는 0 성공, 1 거부(검사를 통과하지 못했거나 아무것도 쓰지 않음), 2 명령이나 인자가 틀림이에요. 1이면 출력의 거부를 읽고 고치고, 2면 친 명령을 다시 봐요.
- npm run 으로 인자나 선택지를 줄 때는 명령 이름 뒤에 `--` 를 두고 적어요(형식 예시: `npm run exams:verify -- https://<정해진 주소>/`). 상대 경로는 명령을 친 폴더 기준이에요. `<...>` 자리는 실제 값으로 바꿔요.
- 모든 명령은 Node 22.18 이상이 필요해요(`node --version`). 낮으면 "Node 22.18 이상이 필요해요."로 끝나요.
- 출력에 비밀 키의 내용은 나오지 않아요. 공개 키의 지문(16자)만 나와요. 정답 파일의 오류와 다른 문항 안내에도 답 값은 나오지 않아요(문항 번호만).

### 1-4. 비밀 키 환경 변수

exams:publish 는 비밀 키를 환경 변수 SA_EXAM_KEY_FILE 이 가리키는 파일에서만 읽어요.

macOS, 리눅스(bash, zsh):

```bash
SA_EXAM_KEY_FILE=<비밀 키 파일 경로> npm run exams:publish
```

Windows PowerShell:

```powershell
$env:SA_EXAM_KEY_FILE = '<비밀 키 파일 경로>'
npm run exams:publish
Remove-Item Env:SA_EXAM_KEY_FILE
```

- 비밀 키 파일이 저장소, 자료 폴더(exam-data), 발행 폴더(dist-exams) 안에 있거나, Ed25519 비밀 키(PEM, PKCS#8)가 아니거나, 테스트 전용 키면 거부해요.
- 비밀 키를 잃어버리면 지금 앱에 든 공개 키로 확인되는 서명을 더는 만들 수 없어요(새 공개 키를 넣은 앱을 다시 내야 해요). 비밀 키가 새어 나가면 다른 사람이 서명할 수 있어요. 보관할 곳과 사본은 키를 맡은 사람이 정해요.

## 2. 전날 점검

| 차례 | 할 일 | 명령 | 확인할 것 |
| --- | --- | --- | --- |
| 1 | 저장소를 팀이 쓰는 최신 상태로 받고 바뀐 파일이 없는지 봐요 | `git pull`, `git status` | 바뀐 파일 없음 |
| 2 | 의존성과 Node 버전 | `npm ci`, `node --version` | v22.18 이상 |
| 3 | 비밀 키 파일의 위치 | 없음(눈으로) | 저장소 밖, 본인만 여는 폴더에 있음. 다른 사람과 나누지 않음 |
| 4 | SA_EXAM_KEY_FILE 과 공개 키의 짝 | SA_EXAM_KEY_FILE 을 넣고 `npm run exams:publish -- --dry-run`. 마지막 발행과 바뀐 것이 없으면 `--allow-same` 도 붙여요(--dry-run 이라 아무것도 쓰지 않아요) | "서명: Ed25519, 공개 키 지문 55ffae2ac148c8a7. 자료 폴더의 public-key.txt 와 짝이에요."(지문은 형식 예시), "메모리에서 서명하고 확인했어요(exams:verify 와 같은 확인).", "결과: 발행하면 위와 같아요. 발행 폴더와 state.json 을 쓰지 않았어요." |
| 5 | 공개 키 | 없음(눈으로) | exam-data/public-key.txt 가 커밋돼 있고, 앱 껍데기에 넣은 공개 키(작업 지시서 4)와 같은 글자 |
| 6 | 원본 검사 | `npm run exams:check` | "거부 0개", "결과: 검사를 통과했어요." 알림은 하나씩 읽고 사실인지 봐요(실제 시험인데 "isSample 이 true" 알림이 나오면 고쳐요) |
| 7 | 지금 올라가 있는 발행물 | `npm run exams:verify -- https://<정해진 주소>/` | "결과: 발행물이 맞아요...", "자료 폴더의 마지막 발행(seq 7, issuedAt 2030-01-02T08:40)과 같아요."(형식 예시). 다르면 종료 코드 1이고 까닭이 나와요(5장). 주소에 발행물이 없을 때만 건너뛰어요 |
| 8 | 잠금 달력 | 6번의 출력 | "잠금 달력(locks.json): 항목 N개" 아래의 항목마다 시각이 주관 기관의 시험 시간표와 같고, 이미 발행돼 있음(7장) |
| 9 | 리허설 결과 | 없음 | 8장의 표에 적은 마지막 리허설에서 막힌 곳을 고쳤음. 단계마다 걸린 시간을 보고 다음 날 일정을 잡았음 |
| 10 | 다음 날 일 나누기 | 없음 | 두 사람, 키를 맡은 사람, 올리는 사람, 서로 연락할 방법 |

## 3. 단계마다 하는 일

### 3-0. 단계마다 같은 일곱 걸음

1. 저장소를 최신으로 받고(`git pull`) 원본을 고쳐요(단계마다 3-1~3-5). 정해진 주소에 발행물이 있으면(잠금 달력을 미리 냈으면 그날의 첫 발행에도) 고치기 전에 `npm run exams:verify -- https://<정해진 주소>/` 로 올라가 있는 것이 자료 폴더의 마지막 발행과 같은지 봐요. 주소에 아무것도 없을 때만 건너뛰어요. 이 컴퓨터의 자료 폴더가 아직 발행한 적이 없는데(seq 0) 주소에 발행물이 있어도 같은 문장이 나와요(별도 검토 2차 T1, 2차 뒤 확인 Y1). "자료 폴더가 최신이 아닐 수 있어요"(종료 코드 1)가 나오면 다른 컴퓨터에서 낸 발행을 아직 받지 못한 것이라 발행하지 않고 먼저 받아요. 최신이 아닌 자료 폴더로 발행하면 같은 seq 의 다른 발행물이나 앞서 낸 시험이 빠진 발행물이 나올 수 있어요(별도 검토 C3).
2. `npm run exams:check` 를 돌리고 두 사람이 변경 요약을 함께 읽어요. "거부 0개" 여야 해요. 알림은 하나씩 사실인지 봐요.
3. SA_EXAM_KEY_FILE 을 넣고 `npm run exams:publish` 를 돌려요. 출력의 seq, issuedAt, 시험마다 rev 와 answersRev, "자료 폴더의 public-key.txt 와 짝이에요."를 봐요. 저장소의 exam-data 에 public-key.txt 가 없으면 발행하지 않아요(키를 맡은 사람이 먼저 만들어 커밋해요).
4. `npm run exams:verify` 로 발행 폴더를 확인해요. "결과: 발행물이 맞아요." 와 "자료 폴더의 마지막 발행(...)과 같아요." 가 나와야 해요.
5. exam-data 의 바뀐 것(src, locks.json, state.json)을 커밋하고 push 해요. state.json 은 다음 발행이 견주는 기준이라 잃어버리면 안 되고, 다음에 발행할 사람이 같은 state.json 을 받아야 해요. dist-exams 는 커밋하지 않아요.
6. dist-exams 의 내용을 정해진 주소에 올려요. files 폴더를 먼저 올리고, index.json 과 index.json.sig 를 마지막에 함께 올려요(docs/시험_배포_규격.md 6장).
7. `npm run exams:verify -- https://<정해진 주소>/` 로 주소에서 확인해요. 4번과 같은 결과여야 해요. 자료 폴더의 마지막 발행과 다르면 종료 코드 1이에요(5장).

publish 의 출력(형식 예시):

```
검사를 통과했어요. 알림 0개.
seq 2(마지막 발행 1), issuedAt 2030-01-02T17:10(한국 시간, 지금 시각), 시험 1개.
  exam-id: rev 2, answersRev 1, sha256 588e315b64d1, files/exam-id.2.json(rev 1에서 2로 바뀌었어요)
잠금 달력: 항목 1개(발행한 것과 같아요).
서명: Ed25519, 공개 키 지문 55ffae2ac148c8a7. 자료 폴더의 public-key.txt 와 짝이에요.
발행 폴더를 새로 만들었어요: dist-exams(index.json, index.json.sig, 시험 파일 1개). 그 전 발행의 파일은 남기지 않았어요.
state.json 을 고쳤어요(seq 1에서 2로).
다음 차례: npm run exams:verify 로 발행 폴더를 확인하고, 정해진 주소에 올린 뒤 그 주소로 한 번 더 확인해요.
```

거부가 있으면 publish 는 "발행하지 않았어요. state.json 과 발행 폴더는 그 전 그대로예요."로 끝나요. 마지막 발행과 바뀐 것이 없어도 발행하지 않아요(단계를 빠뜨린 실수일 때가 많아서). 같은 내용을 새 seq 로 다시 내야 할 때만(발행 폴더를 잃어버렸거나 키를 바꿨을 때) `--allow-same` 을 붙여요.

answers 와 cuts 는 원본이 발행한 판과 달라지면 rev 를 발행한 판 + 1 로 올려 줘요("rev 를 1에서 2로 올렸어요(발행한 판과 내용이 달라서)."). 원본을 손으로 고칠 때는 rev 를 직접 1 올려요. 올리지 않으면 check 가 "내용이 발행한 판과 다른데 rev 가 그대로예요(3). 고쳐 낼 때는 rev 를 4로 올려요."(형식 예시)로 거부해요.

### 3-1. 문항 구성과 배점(정답 공개 전)

원본 시험 파일 exam-data/src/<시험 id>.json 을 새로 만들어요(docs/시험_추가_방법.md 1장의 형식).

- id: 영어 소문자와 숫자를 붙임표(-)로 이은 모양(형식 예시: exam-id)이고 파일 이름과 같아요. 학생 기록이 이 값으로 시험을 찾으니 한 번 정하면 바꾸지 않아요.
- rev 는 1, isSample 과 isPast 는 false, answerReleased 는 false 예요. answer 와 cuts 는 넣지 않아요(발행물은 누구나 받을 수 있는 파일이에요).
- items 에는 문항마다 no, kind, choices(5지선다), points, typeId 를 적어요.
- 유형 분류가 아직이면 "typesReady": false 와 자리만 채우는 유형 하나("t00": { "name": "분류 중" }, 형식 예시)를 두고 모든 문항의 typeId 를 그 유형으로 적어요.
- examDate 는 주관 기관이 발표한 시행일을 알 때만 적어요.

문항 구성(no, kind, choices)은 한 번 발행하면 바꿀 수 없어요(6장). 두 사람이 시험지와 견줘요.

check 의 출력(형식 예시):

```
src/exam-id.json(형식 예시 시험)
  새 시험이에요. rev 1, 문항 30개(5지선다 21개, 단답형 9개), 만점 100점, 정답 공개 전, 유형 분류 전, 등급컷 없음.
```

문항 수, 5지선다와 단답형의 수, 만점이 시험지와 같은지 봐요. 발행하면 학생은 시험 목록에서 이 시험을 고르고 답을 넣어 저장해 둘 수 있어요("정답이 아직 공개되지 않았어요").

### 3-2. 정답

두 사람이 주관 기관이 공개한 정답을 보고 정답 파일을 하나씩 따로 적어요. 서로의 파일을 보거나 베끼지 않아요.

정답 파일(UTF-8 글자 파일, 형식 예시):

```
# 빈 줄과 # 으로 시작하는 줄은 건너뛰어요.
시험 exam-id
1 3
2 5
12 3,5
13 *
22 120
```

- 첫 줄(빈 줄과 # 줄을 뺀 첫 줄)은 `시험 <시험 id>` 예요.
- 한 줄에 `번호 답` 이에요. 5지선다는 1부터 보기 수까지, 단답형은 0부터 999까지예요.
- 복수 정답은 `12 3,5` 처럼 쉼표로 이어요. 앞의 답이 answer(화면에 먼저 보이는 정답), 나머지가 altAnswers 예요. 두 파일은 이 차례까지 같아야 같다고 봐요.
- 모두 정답 처리는 `13 *` 예요.
- 시험의 모든 문항을 한 번씩 적어요. 줄의 차례는 상관없어요.

```bash
npm run exams:answers -- <정답 파일 1> <정답 파일 2>
```

- 두 파일이 같으면: "src/exam-id.json 에 정답을 넣었어요. 문항 30개(복수 정답 0문항, 모두 정답 처리 0문항), answerReleased true." 와 "rev 를 1에서 2로 올렸어요(발행한 판과 내용이 달라서)."(형식 예시). 복수 정답과 모두 정답 처리의 문항 수가 주관 기관의 발표와 같은지 봐요.
- 두 파일이 다르면: "두 정답 파일이 달라요. 다른 문항: 5번."(형식 예시)과 "아무것도 쓰지 않았어요." 두 사람이 그 문항을 각자 원문과 다시 견주고 자기 파일을 고쳐 다시 돌려요. 한 사람의 파일을 다른 사람 것으로 덮어쓰지 않아요.
- 형식이 틀린 줄, 없는 문항, 겹친 문항, 범위 밖 답, 빠진 문항은 파일 이름과 줄 번호로 알려 주고 쓰지 않아요.

check 의 출력에 "정답을 처음 공개해요(answerReleased 가 false 에서 true 로)."가 나와요. 유형 분류가 아직이면 typesReady 는 false 그대로 발행해요. 학생은 앱을 다시 켜지 않아도 저장해 둔 답을 채점하고 점수 해부, 오답 원인, 정답 보기를 쓸 수 있고, 계단 자리에는 "유형 분류를 준비하고 있어요."로 시작하는 안내가 나와요.

### 3-3. 유형 분류

원본을 손으로 고쳐요.

- 문항마다 typeId 를 실제 유형으로 적고, types 에 유형 이름(교육과정 단원 수준)을 적어요. 좌표(coords)는 시험지를 보고 확인한 것만 넣어요(docs/시험_추가_방법.md 4장).
- typesReady 칸을 빼거나 true 로 적어요.
- rev 를 발행한 판 + 1 로 올려요.

check 의 출력에 "유형 분류를 마쳐요(typesReady 가 false 에서 true 로). 계단이 나와요."와 "유형마다 문항 수: 수열 5개, 적분 4개, ..."(형식 예시)가 나와요. 유형 분류 전에 모든 문항이 가리키던 자리만 채우는 유형을 아직 가리키는 문항이 있으면 알림이 나와요. 유형 분류를 마친 뒤 유형을 고치면 "유형이 바뀌는 문항: 1번(발행한 판 수열, 지금 적분)"(형식 예시)과 "유형 이름이 바뀌어요"가 나와요. 두 사람이 유형별 문항 수와 바뀌는 문항을 함께 봐요. 발행하면 학생 화면에 계단이 나와요.

### 3-4. 추정 등급컷

기관별 추정 컷을 모아 입력 파일(JSON)을 만들어요. 기관마다 쓸 수 있는 범위와 조건은 docs/자료_이용_근거.md 에 적어 두고 그 안에서 써요. 바깥 사이트에서 자동으로 모으는 도구는 없어요(사람이 적어요).

입력 파일(형식 예시, 값은 예시 값이에요):

```json
{
  "format": 1,
  "exam": "exam-id",
  "asOf": "2030-01-02T20:10",
  "estimates": [
    { "source": "기관 가", "grades": { "1": 88, "2": 81, "3": 72 } },
    { "source": "기관 나", "grades": { "1": 92, "2": 85, "3": 76 } }
  ]
}
```

- asOf 는 이 자료의 기준 시각이에요(한국 시간, 날짜와 시각). 날짜만은 받지 않아요.
- estimates 는 기관마다 하나예요. source 는 기관 이름(겹치면 거부), grades 는 등급별 원점수 컷 하나(정수)예요.
- 나중에 수집 도구가 생기면 이 모양 그대로 만들면 돼요.

```bash
npm run exams:cuts -- <추정 컷 파일>
```

출력(형식 예시):

```
src/exam-id.json 의 등급컷을 썼어요. 추정(confirmed false), 기준 2030-01-02T20:10, 기관 2곳(기관 가, 기관 나).
  1등급 컷 88~92점
  2등급 컷 81~85점
  3등급 컷 72~76점
```

- 등급마다 기관들의 가장 낮은 값과 가장 높은 값으로 범위를 만들고, source 는 "기관 가, 기관 나의 추정 가운데 가장 낮은 값과 가장 높은 값", confirmed 는 false 로 들어가요. 기관이 한 곳이면 "2등급 컷 82점"처럼 한 값이고 source 는 "기관 가의 추정 값"이에요(형식 예시).
- 거부하는 것: 값이 0보다 작거나 만점보다 큼, 높은 등급의 컷이 낮은 등급의 컷보다 낮음, 정수가 아님, 기관 이름이 겹침, 지금 컷이 주관 기관이 발표한 컷(confirmed true), 지금 컷의 기준보다 이른 시각. 거부하면 원본을 쓰지 않아요.
- 기관마다 적은 등급이 다르면 모든 기관이 적은 등급만 넣고 뺀 등급을 알려요.
- 새 추정이 나오면 더 늦은 asOf 로 같은 명령을 다시 돌려요. 학생 화면의 기준 시각과 범위가 바뀌어요.
- check 의 출력에 "등급컷을 처음 넣어요(추정, 기준 2030-01-02T20:10, 등급 3개)."나 "등급컷이 바뀌어요(...)"가 나와요.
- 앱은 등급컷을 스스로 예측하지 않아요. 여러 기관 추정치의 가장 낮은 값과 가장 높은 값만 보여 줘요.

### 3-5. 성적 발표 뒤 자료

- "확정" 배지는 주관 기관이 원점수 등급컷을 직접 발표했을 때만 써요. 그때는 원본을 손으로 고쳐요: cuts 의 confirmed 를 true 로, grades 의 두 값을 발표한 값으로 같게(형식 예시: "2": [82, 82]), source 에 발표한 기관, asOf 에 발표 시각, rev 를 발행한 판 + 1 로 적어요. 두 사람이 발표와 값을 견줘요.
- check 의 출력에 "등급컷이 바뀌어요(발행한 판: 추정, 기준 ..., 지금: 확정, 기준 ...)."가 나와요. confirmed 가 true 인데 두 값이 다르면 거부돼요.
- 주관 기관이 원점수 등급컷을 발표하지 않으면, 성적 발표 뒤에 업체가 계산한 값도 추정이에요. 3-4처럼 exams:cuts 로 넣어요(confirmed false).
- 확정 컷을 넣은 뒤에는 exams:cuts 가 "지금 등급컷이 주관 기관이 발표한 컷(confirmed true)이라 추정 컷으로 바꾸지 않아요."로 거부해요.

## 4. 두 사람 확인

- 정답: 두 사람이 정답 파일을 따로 적어요. exams:answers 는 두 파일이 완전히 같을 때만 써요(복수 정답은 차례까지). 같은 파일을 두 번 주면 거부해요.
- 발행 전: check 의 변경 요약을 두 사람이 함께 읽어요. rev 와 answersRev, 정답 공개와 정정의 문항 번호, 정정 안내 문장, 등급컷의 기준 시각과 등급 수, 잠금 달력의 시각을 봐요.
- 추정 컷: 한 사람이 입력 파일을 만들면 다른 사람이 기관 자료와 값을 하나씩 견줘요.
- 확정 컷과 잠금 달력: 다른 사람이 주관 기관의 발표와 견줘요.
- 올린 뒤: 다른 사람도 저장소를 받은 뒤(git pull) 자기 컴퓨터에서 `npm run exams:verify -- https://<정해진 주소>/` 를 돌려요.

## 5. 발행 뒤 확인(exams:verify)

발행 폴더를 확인해요.

```bash
npm run exams:verify
```

출력(형식 예시):

```
발행물을 확인해요: dist-exams
공개 키: exam-data/public-key.txt(지문 55ffae2ac148c8a7).
서명이 맞아요(index.json.sig).
seq 2, issuedAt 2030-01-02T17:10(한국 시간), 시험 1개, 잠금 달력 항목 1개.
  exam-id: rev 2, sha256 588e315b64d1, files/exam-id.2.json, 맞아요.
자료 폴더의 마지막 발행(seq 2, issuedAt 2030-01-02T17:10)과 같아요.
결과: 발행물이 맞아요. 서명, 시험 파일의 SHA-256 과 검사, 잠금 달력이 모두 맞아요.
```

올린 뒤에는 주소로 확인해요. 캐시를 쓰지 않고 받아요.

```bash
npm run exams:verify -- https://<정해진 주소>/
```

- 위와 같은 결과(종료 코드 0)여야 해요. 결과 줄과 종료 코드를 함께 봐요.
- 서명과 SHA-256 이 맞아도 자료 폴더의 마지막 발행과 다르면 "결과: 주소의 발행물이 자료 폴더의 마지막 발행과 달라요.", 견주지 못하면 "결과: 주소의 발행물을 자료 폴더의 마지막 발행과 견주지 못했어요."와 종료 코드 1이에요(별도 검토 C2, 2차 T1, T4, 2차 뒤 확인 Y3). 까닭은 아래 넷 가운데 하나로 나와요.
  - "보다 예전 것이에요": 새 발행물이 아직 다 올라가지 않았거나 캐시가 남은 것이에요. 올린 파일과 캐시를 보고 다시 확인해요.
  - "보다 새로워요": 자료 폴더가 최신이 아니에요(자료 폴더가 아직 발행한 적이 없을 때도 나와요). `git pull` 로 받은 뒤 다시 확인하고, 그 전에는 발행하지 않아요.
  - "다른 자료 폴더에서 같은 seq 로 발행했을 수 있어요": seq 는 같은데 issuedAt, 시험 목록과 SHA-256, 잠금 달력 가운데 하나가 달라요. 키를 맡은 사람과 확인해요.
  - "견주지 못했어요": 자료 폴더의 state.json 이 없거나 읽지 못하거나 모양이 틀려요(git pull 의 충돌 표시가 남은 경우 등). 받고 충돌을 푼 뒤 --data 가 맞는지 보고 다시 확인해요. 그 전에는 발행하지 않아요.
- 발행 폴더를 확인할 때(`npm run exams:verify`)는 마지막 발행과 다르거나 견주지 못해도 알리기만 해요(실패는 아님). 테스트 전용 공개 키로 확인하면 자료 폴더와 견주지 않아요(테스트 전용 발행물은 진짜 자료 폴더와 상관이 없어요). 자료 폴더가 아직 발행한 적이 없으면(seq 0) 폴더 확인은 견주지 않고 알리지도 않아요.
- "결과: 발행물이 맞지 않아요."(종료 코드 1)면 이유 목록을 봐요. 서명이 맞지 않으면 index.json 이 바뀌었거나 다른 키로 서명한 것이고, sha256 이 맞지 않으면 시험 파일이 덜 올라갔거나 바뀐 것이에요. 발행 폴더를 다시 올리고 다시 확인해요. 그동안 학생 기기는 그 발행물을 버리고 가진 자료를 그대로 써요.
- "공개 키 파일이 없어요"가 나오면 exam-data/public-key.txt 가 없는 것이에요(키를 맡은 사람이 만들어 커밋해요).

## 6. 잘못 냈을 때 고쳐 내는 법

되돌리기는 없어요. 한 번 낸 발행물은 학생 기기에 남을 수 있고, 받는 쪽은 seq 가 작은 발행물을 버려요. 원본을 고쳐 rev 를 올리고 다시 발행하면(seq 는 도구가 올려요) 기기가 다음에 받을 때 고친 판으로 바뀌어요. state.json 을 손으로 고치거나 발행한 시험의 원본 파일을 지우지 않아요(도구가 거부해요).

| 잘못 낸 것 | 고치는 법 |
| --- | --- |
| 정답(정답 공개 뒤) | 두 사람이 고친 정답 파일을 다시 따로 적어 `npm run exams:answers -- <정답 파일 1> <정답 파일 2> --note "<정정 안내>"` 를 돌려요. answersRev 가 발행한 판 + 1, answersNote 가 정정 안내, rev 가 발행한 판 + 1 이 돼요. check 에 "정답 정정: 채점이 바뀌는 문항 2번(정답). answersRev 가 1에서 2로 올라요. 정정 안내: ..."(형식 예시)가 나와요 |
| 배점(정답 공개 뒤) | 배점도 채점에 영향을 주는 값이라 정정이에요. 원본의 points 를 고치고 answersRev 를 발행한 판 + 1, answersNote 에 정정 안내, rev 를 발행한 판 + 1 로 손으로 고쳐요. 학생 알림의 첫 줄은 정답 정정과 같이 "정답이 정정돼서"(점수가 바뀜)나 "정답이 정정됐지만"(점수가 그대로)으로 시작해요(작업 지시서 3의 4-6이 정한 문장). 그래서 answersNote 에 배점 정정이라고 적어요(형식 예시: 12번 배점이 정정됐어요.) |
| 배점(정답 공개 전) | points 를 고치고 rev 를 1 올려요. 정답 공개 전이라 정정이 아니어서 answersRev 는 그대로예요 |
| 정정 안내 문장만 | answersNote 를 고치고 rev 를 1 올려요. answersRev 는 그대로예요 |
| 유형 분류 | typeId 와 types 를 고치고 rev 를 1 올려요 |
| 추정 등급컷 | 고친 입력 파일로 exams:cuts 를 다시 돌려요. asOf 는 지금 컷의 기준과 같거나 늦어야 해요 |
| 확정 컷 | 원본을 손으로 고치고 rev 를 1 올려요. check 가 "발표를 다시 확인해 주세요" 알림을 내요 |
| 잠금 달력 | exam-data/locks.json 을 고쳐 다시 발행해요. 같은 id 의 항목을 고치면 기기에서도 그 항목이 바뀌고, 항목을 빼면 다음 발행부터 빠져요 |
| 문항 구성(no, kind, choices) | 발행한 시험에서는 바꿀 수 없어요(도구가 거부해요). 새 id 로 고친 시험을 새로 내요. 앞의 시험은 지울 수 없어 목록에 남고, 제목과 안내(note)는 rev 를 올려 고칠 수 있어요 |
| 정답 공개 | 공개한 정답은 거둘 수 없어요(answerReleased 를 false 로 돌리면 거부해요) |

- 정정 안내(answersNote)는 학생이 "정답 보기"를 누르기 전에 보는 문장이에요. 정답 값을 쓰지 않고 문항 번호만 적어요(형식 예시: "12번 정답이 정정됐어요."). "3번에서 5번으로"처럼 정답 값으로 보이는 글자가 있으면 도구가 알려요.
- 정정 안내에는 정답 공개 뒤의 정정을 모두 적어요(형식 예시: "7번과 12번 정답이 정정됐어요."). 학생 알림은 채점한 때의 점수에서 지금 점수로 바뀐 것과 지금 판의 정정 안내 한 문장만 보여 줘서, 앞선 정정을 받지 못했거나 확인하지 않은 학생은 앞선 정정의 까닭을 볼 곳이 없어요. 두 번째 이상의 정정이면 check 와 answers 가 이것을 알려요(별도 검토 B3, D4).
- 정정해도 학생이 넣은 답과 표시는 바뀌지 않아요. 앱이 지금 정답으로 다시 채점하고 "정답이 정정돼서 다시 채점했어요."로 시작하는 알림과 정정 안내를 보여 줘요.
- `--issued-at` 은 리허설에서만 써요(주지 않으면 지금의 한국 시각이 들어가요). 지금보다 늦은 시각을 잘못 주면 그 뒤 발행도 그 시각보다 이를 수 없어서 되돌릴 수 없어요.

## 7. 잠금 달력을 넣는 법

- 수능, 평가원 모의평가, 전국연합학력평가가 치러지는 시간에는 풀이 계열 기능을 보여 주지 않아요. 시간대는 일반 수험생 기준 1교시 시작부터 마지막 교시 종료까지이고 한국 시간이에요. 지금 앱에는 풀이 계열 기능이 없어서, 잠금이 보이는 곳은 진행자용 화면의 한 줄("풀이 잠금: 지금 잠김(오후 5시 45분까지)", 형식 예시)뿐이에요.
- 시험 시간은 지어내지 않아요. 주관 기관이 발표한 시험 시간표를 확인한 사람이 넣고, 다른 사람이 견줘요.
- 시험 날 쓰는 달력은 exam-data/locks.json 이에요(발행할 때 index.json 의 locks 로 나가요). 앱 묶음 안 달력(src/exams/locks.json)은 앱을 새로 내야 바뀌어서 시험 날에는 쓰지 않아요.

항목(형식 예시):

```json
[
  {
    "id": "exam-id-lock",
    "label": "형식 예시 시험의 1교시 시작부터 마지막 교시 종료까지",
    "start": "2030-01-02T08:40",
    "end": "2030-01-02T17:45"
  }
]
```

- id 는 항목 이름이에요. 달력 안에서 겹치면 안 되고, 나중에 시각을 고칠 때도 같은 id 를 써요.
- label 은 사람이 보는 메모예요. 화면에 쓰지 않지만 비우지 않아요.
- start 와 end 는 "YYYY-MM-DDTHH:mm"(한국 시간, 두 자리)이고 같은 날이에요. start 부터 잠기고 end 에 풀려요(start 이상 end 미만). 시험이 여러 날이면 날마다 항목을 하나씩 둬요.
- 시험 날 아침이 아니라 며칠 앞서 발행해요. 학생 기기가 시험 시간에 통신이 없을 수 있어서, 그 전에 받아 두어야 맞게 잠겨요.
- check 의 출력에서 "잠금 달력(locks.json): 항목 1개, 발행한 것과 달라요." 와 "exam-id-lock: 2030-01-02T08:40부터 2030-01-02T17:45까지"(형식 예시)를 시간표와 견준 뒤 3-0의 걸음대로 발행해요. 형식이 틀리면 check 와 publish 가 거부해요.
- 앞으로 풀이 계열 기능을 더하는 작업은 반드시 이 판정을 거쳐요(docs/결정기록.md 6장).

## 8. 리허설

시험 날 순서를 테스트 자료로 한 번 끝까지 해 보고, 단계마다 걸린 시간을 아래 표에 적어요.

- 저장소의 exam-data 로 리허설하지 않아요. 발행하면 state.json 의 seq 와 발행한 시험 id 가 남아서 진짜 발행에 섞여요.
- 테스트 전용 키(exam-data/testdata)는 exams:publish 가 거부해요. 진짜 키도 쓰지 않아요. 리허설 때마다 exams:keygen 으로 새로 만든 임시 키를 써요.

1. 저장소 밖에 임시 폴더를 만들어요(아래에서 `<임시 폴더>`). `<임시 폴더>/data/src` 와 `<임시 폴더>/key` 폴더를 만들고, `<임시 폴더>/data/locks.json` 에 `[]` 를, `<임시 폴더>/data/state.json` 에 아직 발행한 적이 없는 처음 값을 적어요.

   ```json
   {
     "exams": {},
     "format": 1,
     "issuedAt": null,
     "locksSha256": null,
     "seq": 0
   }
   ```

2. 임시 키를 만들어요. "공개 키를 썼어요: ...(지문 ...). 이 자료 폴더는 저장소의 exam-data 가 아니라서 커밋하지 않아요."가 나와요.

   ```bash
   npm run exams:keygen -- <임시 폴더>/key/rehearsal-private-key.pem --data <임시 폴더>/data
   ```

3. 리허설용 시험을 만들어요. 예시 시험 C(src/exams/sample-c.json, 정답 공개 전 예시 시험)를 `<임시 폴더>/data/src/rehearsal-exam.json` 으로 복사하고, id 를 "rehearsal-exam", title 을 "리허설 전용 시험"으로 바꾸고 "rev": 1 을 더해요. 3-3도 연습하려면 3-1처럼 유형을 자리만 채우는 유형 하나로 바꾸고 "typesReady": false 를 더해요. isSample 은 true 그대로 둬요(check 에 알림이 하나 나와요).
4. SA_EXAM_KEY_FILE 을 임시 키로 하고, check, answers, cuts, publish 에는 `--data <임시 폴더>/data` 를, publish 에는 `--out <임시 폴더>/out` 도 붙여 3장의 단계를 차례로 해요. verify 는 `npm run exams:verify -- <임시 폴더>/out --data <임시 폴더>/data` 예요. 도구의 "다음 차례" 안내에도 준 --data 와 발행 폴더가 붙어 나와요(그대로 쳐도 임시 폴더를 봐요).
   - 정답: 두 사람이 예시 시험 A(src/exams/sample-a.json)의 answer 를 따로 옮겨 적어요(예시 시험 A와 C는 문항 구성과 배점이 같아요). 한 번은 일부러 한 문항을 다르게 적어 "다른 문항" 출력도 봐요.
   - 유형 분류: 예시 시험 C의 typeId 와 types 로 되돌리고 rev 를 올려요.
   - 추정 등급컷: 3-4의 형식 예시 입력 파일로 해요.
   - 정답 정정: 두 정답 파일에서 같은 문항 하나를 바꾸고 `--note "2번 정답이 정정됐어요."`(형식 예시)로 해요.
   - 성적 발표 뒤: 3-5처럼 확정 컷을 손으로 넣어요(값은 예시 값).
   - 잠금 달력: 7장의 형식 예시 항목 하나를 넣어요.
5. 리허설 서버로 주소 확인을 연습해요. 한 창에서 서버를 띄우고, 다른 창에서 확인해요. 서버는 이 컴퓨터(127.0.0.1)에서만 열리고 TLS 가 없어요. 끄기는 Ctrl+C 예요.

   ```bash
   npm run exams:serve -- --dir <임시 폴더>/out
   npm run exams:verify -- http://127.0.0.1:4180/ --data <임시 폴더>/data
   ```

   서버가 적는 확인 안내는 기본이 아닌 발행 폴더라서 `--data <발행할 때 쓴 자료 폴더>` 를 붙이라고 나와요. 위 둘째 줄처럼 임시 자료 폴더를 붙여요(붙이지 않으면 저장소의 exam-data 로 확인해서 맞지 않아요).

   작업 지시서 4의 껍데기가 생기면 시뮬레이터의 Debug 빌드가 이 주소에서 받는 것까지 해 봐요(아직 확인하지 못했어요).
6. 끝나면 임시 폴더(임시 키 포함)를 지우고, 저장소에서 `git status` 로 바뀐 파일이 없는지 봐요.

이 순서(임시 키, 예시 시험 C 사본, 정답 같음과 다름, 유형 분류, 추정 컷, 정답 정정, 확정 컷, 잠금 달력, 바뀐 것이 없는 발행, 리허설 서버와 주소 확인)는 이 문서를 쓰며 저장소 밖의 임시 폴더에서 `node scripts/exams.mjs` 로 한 번 끝까지 돌려 봤고, 명령마다 기대한 종료 코드와 출력이 나왔어요. npm run 으로 `--note` 의 띄어 쓴 문장이 한 값으로 넘어가는 것은 Git Bash 와 PowerShell 에서 따로 봤어요. 사람이 하는 데 걸린 시간은 재지 않았어요.
