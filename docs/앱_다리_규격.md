# 앱 다리 규격 (규격 번호 1)

결론: 아이폰 앱은 화면 전체를 차지하는 웹뷰 하나에 이 저장소의 앱용 묶음(단일 HTML)을 싣는 얇은 껍데기예요. 화면과 계산은 웹 코드가 맡고, 껍데기는 기록 파일 저장, 햅틱, 글자 크기 전달, 복사만 맡아요. 웹과 껍데기는 아래 약속(다리)으로만 주고받아요. 이 문서는 작업 지시서 1의 6-2를 그대로 옮기고, 웹 쪽 구현(src/platform/app.ts)이 실제로 지키는 세부를 더한 것이에요. 작업 지시서 2(iOS 앱 껍데기)가 이 문서를 구현해요. 껍데기가 받아 온 시험 자료를 웹에 넘겨주는 규격 2는 7장에 있어요(작업 지시서 3).

## 1. 껍데기가 넣어 주는 값

껍데기는 문서가 시작될 때(문서의 다른 스크립트보다 먼저, 페이지 콘텐츠 세계에) `window.__SA_APP__` 를 객체로 넣어 줘요(JSON 글자가 아니라 객체).

| 칸 | 값 | 뜻 |
| --- | --- | --- |
| platform | "ios" | 껍데기 종류 |
| bridge | 1 | 다리 규격 번호. 이 문서의 번호와 같아야 해요 |
| appVersion | 문자열(예: "0.2.0") | 앱 버전 |
| store | 저장된 JSON 문자열 또는 null | 앱 전용 파일(store.json)의 내용. 파일이 없으면 null. 파일이 있는데 글자로 읽지 못하면 null 이 아니라 빈 글자("")를 넣어요(웹이 보관을 먼저 요청해요) |
| fontScale | 1 이상 2 이하의 숫자 | 기기의 글자 크기 설정에서 구한 배율. 기본 크기에서 1 |

`window.__SA_APP__` 도 다리(`window.webkit.messageHandlers.saStore`)도 없으면(브라우저에서 열면) 웹은 브라우저 방식으로 동작해요(기록은 localStorage, 복사는 브라우저 방식, 브라우저 문구). 배포용 묶음은 브라우저로 열어도 진행자용 화면, 5행 방식, "준비 중인 기능" 목록이 없어요(묶음에서 빠져 있어요).

껍데기 안인데 다리를 쓸 수 없으면(`__SA_APP__` 가 객체가 아니거나 없는데 다리가 있음, bridge 가 이 문서의 번호와 다름) 웹은 다리로 아무것도 보내지 않아요. 기록을 읽지도 저장하지도 않고(store.json 을 건드리지 않고 localStorage 에도 쓰지 않아요) 저장하지 못했다는 안내를 보여 줘요. 복사는 브라우저 방식으로 해 보고, 햅틱은 보내지 않아요.

## 2. 웹이 껍데기로 보내는 것

`window.webkit.messageHandlers.<이름>.postMessage(값)` 으로 보내요.

| 이름 | 값 | 언제 | 껍데기가 할 일 |
| --- | --- | --- | --- |
| saStore | `{ op: "save", json: 문자열 }` | 저장할 때마다(기록 전체를 JSON 글자 하나로) | store.json 에 저장해요. 요청이 여러 번 오면 순서대로 처리하고 마지막 것이 남아요. 실패하면 원래 파일을 건드리지 않고 storeFailed 로 알려요 |
| saStore | `{ op: "archive" }` | 받은 store 를 읽지 못했을 때, 그 기록을 덮어쓰기 전에 한 번. 웹은 곧바로 이어서 save(보관 안내 표시가 든 새 기록)를 보내요 | store.json 을 지우지 않고 다른 이름으로 보관해요(예: store-보관-날짜시각.json). 보관하지 못하면 store.json 을 그대로 두고, 그 실행에서 오는 save 는 처리하지 않고 storeFailed 로 알려요 |
| saHaptic | `"key"` | 받아들인 키패드 누름 한 번에 한 번 | 가벼운 햅틱 한 번. 잠긴 키와 버려진 누름에는 보내지 않아요 |
| saCopy | 복사할 문자열 | 좌표 복사, 진행자용 화면의 복사 | 이 기기의 클립보드에만 넣고 copied 로 결과를 알려요. saCopy 하나에 copied 를 꼭 하나, 받은 차례대로 보내요(3초가 지나도 보내요. 웹은 시간이 지나 실패로 끝낸 요청 수만큼 늦은 답을 건너뛰어요) |

## 3. 껍데기가 웹에 알리는 것

`window.__saFromApp(메시지)` 를 불러요. 웹은 묶음의 스크립트가 실행될 때(문서를 다 읽은 뒤) 이 함수를 만들어요. 그래서 껍데기는 페이지 읽기가 끝난 뒤(didFinish)부터 불러요. 그 전에 바뀐 글자 크기는 그때 다시 보내요. 껍데기 안이면 `__SA_APP__` 가 잘못 들어와도 이 함수는 만들어져요.

| 메시지 | 언제 | 웹이 하는 일 |
| --- | --- | --- |
| `{ type: "storeFailed" }` | saStore 의 save 를 저장하지 못했을 때(보관하지 못한 뒤의 save 포함) | 기록 화면에 "이 기기에 기록을 저장하지 못했어요. 화면은 그대로 쓸 수 있어요."를 보여 줘요. 그 실행에서 처음 실패했으면 지금 화면 위쪽에도 4초 동안 한 번 알려요. 다음 save 를 보내면 기록 화면의 안내를 내리고, 그 save 도 실패하면 다시 띄워요(성공 알림은 없어요) |
| `{ type: "fontScale", value: 숫자 }` | 기기의 글자 크기 설정이 바뀌었을 때 | 루트 글자 크기를 바로 바꿔요 |
| `{ type: "copied", ok: 참거짓 }` | saCopy 를 처리한 뒤 | 보낸 차례대로 하나씩 결과로 받아요. ok가 false면 "복사하지 못했어요"를 보여 줘요 |

## 4. 웹이 지키는 것(src/platform/app.ts, src/state/store.ts)

- 앱에서는 localStorage 를 쓰지 않고 다리로만 읽고 써요. 읽기는 시작할 때 `__SA_APP__.store` 를 한 번 읽는 것뿐이에요.
- store 가 null이면(칸이 없어도) 새로 시작해요(보관 요청 없음). null 이 아니면서 글자가 아닌 값(객체, 숫자 등)은 읽을 수 없는 것으로 봐요.
- store 를 통째로 읽을 수 없거나(JSON이 아님, 객체가 아님, version 이 숫자가 아님) version 이 웹이 아는 값(1)보다 크면 덮어쓰지 않아요. archive 를 먼저 보낸 뒤 새로 시작하고, 기록 화면에 "앞서 저장된 기록을 읽지 못해 따로 보관해 뒀어요."를 보여 줘요. 빈 글자("")도 읽을 수 없는 것으로 봐요. 새로 시작한 기록에는 보관 안내 표시(archiveNotice: true)를 넣어 곧바로 저장하고, 기록 화면이 안내를 보여 준 뒤 표시를 지워요(앱을 끄고 다시 켜도 한 번은 보여요). archive 를 보내지 못하면 그 실행 동안 저장하지 않아요.
- version 이 1보다 작으면 옮기는 함수를 거쳐요. 지금은 version 1뿐이라 틀만 있고, 옮기지 못하면 읽을 수 없는 것으로 봐요.
- 일부만 망가진 기록(모양이 맞지 않는 칸)은 지금처럼 모양이 맞는 값만 남기고 읽어요. 이때는 보관하지 않아요.
- 저장은 늘 기록 전체를 보내요. 받은 순서대로 쓰면 마지막 것이 지금 상태예요.
- 루트 글자 크기는 16px x fontScale 이에요. 1보다 작은 값은 1로, 2보다 큰 값은(무한대도) 2로, 숫자가 아니면(NaN 포함) 1로 봐요. 화면의 글자 크기는 모두 rem 이라 함께 커져요.
- copied 를 3초 안에 받지 못하면 복사하지 못한 것으로 봐요. 그 요청의 늦은 답은 건너뛰어요.
- 앱 안에서만 바꾸는 문구: 시작 화면 "가입 없이 써요. 기록은 이 기기에 저장하고 서버로 보내지 않아요.", 기록 화면 아래 "앱을 지우면 기록도 함께 지워져요.", 저장 실패 문구. 진행자용 화면(시험용 묶음)은 "파일 저장" 버튼을 빼고 복사만 둬요.
- 길게 눌렀을 때 글자 선택이나 미리보기가 뜨지 않게 하고(글을 적는 칸과 좌표 목록은 빼고), 화면 끝에서 당겨도 화면 전체가 끌려오지 않게 해요(html.sa-app 의 CSS). 껍데기도 웹뷰의 미리보기와 튕김을 꺼 주면 좋아요.
- 바깥으로 나가는 요청은 없어요. 묶음은 스크립트와 스타일을 파일 안에 담고, 글꼴은 기기의 시스템 글꼴을 써요(글꼴 파일이 없어요). 파일 하나로 넣을 수 없는 자산(그림, 글꼴 파일)이 생기면 `npm run build:app` 이 실패해요.

- 셋 다 커밋해요. 맥에서는 Node 없이 이 파일만 써요.
- 만드는 명령은 `npm run build:app` 이에요. 같은 코드에서는 같은 묶음(같은 SHA-256)이 나와요. `npm run verify`(11번)가 지금 코드로 두 번 다시 만들어 HEAD 에 커밋된 묶음, manifest 의 SHA-256 과 같은지 확인해요. 세 파일이 커밋돼 있고 작업 폴더와 같은지, manifest 의 dirty 가 false 이고 그 커밋이 HEAD 의 조상이며 그 뒤로 묶음 재료가 바뀌지 않았는지도 봐요.
- 줄바꿈 변환으로 바이트가 바뀌지 않게 .gitattributes 에서 이 폴더를 -text 로 둬요.

## 6. 규격을 바꿀 때

- 웹과 껍데기 가운데 한쪽만 바뀌는 변경(메시지 추가, 값의 뜻 변경)은 규격 번호를 올리고 이 문서(제목과 1장 표)와 src/platform/app.ts 의 BRIDGE_VERSION 을 함께 고쳐요. scripts/app-bundles.mjs 는 app.ts 에서 번호를 읽고, 단위 테스트가 문서 제목과 표의 번호가 app.ts 와 같은지 봐요.
- 껍데기는 `__SA_APP__.bridge` 로 자기가 따르는 번호를 알려 주고, 웹은 그 번호가 자기 번호와 같을 때만 다리를 써요(다르면 1장의 "다리를 쓸 수 없으면"대로 해요). manifest.json 의 bridge 는 묶음이 따르는 번호예요. 껍데기는 묶음을 실을 때 이 값이 자기 번호와 같은지 보면 돼요.

## 7. 규격 2

규격 2는 껍데기가 정해진 주소에서 받아 확인한 시험 자료를 웹에 넘겨주는 약속이에요(작업 지시서 3의 5장). 받는 일과 서명 확인은 껍데기가 하고, 웹은 넘겨받은 자료를 검사해서 쓸 뿐 스스로 통신하지 않아요. 1~6장(규격 1)의 내용은 바꾸지 않았고, 규격 2 껍데기와도 규격 1의 일을 똑같이 해요.

### 7-1. 작업 지시서 3의 5-1

아래 네 항목은 작업 지시서 3의 5-1을 그대로 옮겼어요. 6-3은 작업 지시서 3의 6-3(받는 쪽 규칙: 서명 확인, format 확인, seq 가 작은 자료 버리기, 시험 파일의 sha256 확인, 모두 확인한 뒤 한 번에 바꾸기, 받아들인 자료를 기기에 보관하기 등)이에요.

- 껍데기가 넣어 주는 `window.__SA_APP__` 의 bridge 가 2 이상이면 remote 칸이 올 수 있다. 값은 null 이거나 `{ seq, issuedAt, exams, locks }` 다. seq 는 정수, issuedAt 은 "YYYY-MM-DDTHH:mm"(한국 시간), exams 는 시험 파일 내용의 배열, locks 는 잠금 달력이다.
- 껍데기가 웹에 알리는 것(`window.__saFromApp` 호출): `{ type: "remote", remote: 위와 같은 값 }`, `{ type: "remoteFailed" }`.
- 웹이 껍데기로 보내는 것: saRemote 로 `{ op: "refresh" }`.
- 껍데기는 6-3의 받는 쪽 규칙을 모두 통과한 자료만 remote 로 넘긴다.

### 7-2. 규격 번호와 manifest.json

- 웹은 규격 1과 2를 받아요. `__SA_APP__.bridge` 가 1 이상 2 이하의 정수면 다리를 쓰고, 그 밖의 값(0, 3 이상, 1.5, 글자 "2" 등)이면 1장의 "다리를 쓸 수 없으면"대로 해요. 1장 표의 "이 문서의 번호와 같아야 해요"와 6장의 "같을 때만 다리를 써요"는 규격 1만 있을 때의 글이고, 규격 2부터는 이 장을 따라요.
- 규격 1의 일(saStore 의 저장과 보관, saHaptic, saCopy 와 copied, storeFailed, fontScale)은 bridge 가 1이어도 2여도 똑같아요.
- manifest.json 의 bridge 는 이 묶음이 돌아가는 가장 낮은 규격이에요. 규격 1 껍데기에서도 돌아야 해서 1 그대로예요. 새 칸 bridgeMax 는 웹이 아는 가장 높은 규격(2)이에요. 둘 다 scripts/app-bundles.mjs 가 src/platform/app.ts 의 BRIDGE_VERSION 과 BRIDGE_MAX 에서 읽어 적고, `npm run verify`(11번)가 둘 다 견줘요. 이 문서 제목의 번호는 BRIDGE_VERSION 과 같아서 가장 낮은 규격이에요.
- 껍데기는 묶음을 실을 때 자기 규격 번호가 bridge 이상 bridgeMax 이하인지 보면 돼요. 6장대로 bridge 가 자기 번호와 같은지 보는 규격 1 껍데기는 bridge 가 1 그대로라 지금처럼 실을 수 있어요(bridgeMax 칸은 몰라도 돼요).

manifest.json 의 칸:

| 칸 | 값 | 뜻 |
| --- | --- | --- |
| name | "score-anatomy" | 묶음 이름 |
| commit | 커밋 해시(40자) 또는 null | 묶음을 만든 때의 커밋. git 을 쓸 수 없었으면 null |
| dirty | 참거짓 또는 null | 그때 묶음 재료(scripts/app-bundles.mjs 의 INPUTS)에 커밋하지 않은 바뀜이 있었는지. git 을 쓸 수 없었으면 null |
| version | 문자열(예: "0.2.0") | package.json 의 버전 |
| bridge | 1 | 이 묶음이 돌아가는 가장 낮은 다리 규격(src/platform/app.ts 의 BRIDGE_VERSION) |
| bridgeMax | 2 | 웹이 아는 가장 높은 다리 규격(src/platform/app.ts 의 BRIDGE_MAX) |
| files | 묶음 파일 경로("app-test/index.html", "app-release/index.html")마다 `{ sha256, bytes }` | 파일별 SHA-256(16진수 소문자)과 크기(바이트) |

### 7-3. 규격 2에서 더한 메시지

웹이 껍데기로 보내는 것:

| 이름 | 값 | 언제 | 껍데기가 할 일 |
| --- | --- | --- | --- |
| saRemote | `{ op: "refresh" }` | 시험 선택 화면의 "새로 확인"을 눌렀을 때 | 정해진 주소에서 자료를 다시 받아 6-3대로 확인한 뒤 remote 나 remoteFailed 를 하나 보내요. 새 자료가 없으면 지금 가진 자료를 seq 그대로 remote 로 보내요 |

껍데기가 웹에 알리는 것:

| 메시지 | 언제 | 웹이 하는 일 |
| --- | --- | --- |
| `{ type: "remote", remote: 값 }` | 새로 확인의 응답, 그리고 켜져 있는 동안 새 자료를 받아들였을 때 | seq 가 지금 쓰는 자료보다 크면 시험 목록과 잠금 달력을 새 자료로 바꾸고 지금 보고 있는 화면을 다시 그려요. 같거나 작으면(remote 가 null 이어도) 자료를 바꾸지 않아요 |
| `{ type: "remoteFailed" }` | 새로 확인에서 자료를 받지 못했거나 확인을 통과하지 못했을 때 | 가진 자료를 그대로 써요 |

### 7-4. 웹이 지키는 것

- 껍데기가 규격 1이면 remote 를 넣지 않고, 웹도 remote 칸과 remote, remoteFailed 알림을 보지 않고 saRemote 를 보내지 않아요. 브라우저에서 열 때처럼 묶음 안 시험만 써요.
- 규격 2 이상이면 웹은 시작할 때 `__SA_APP__.remote` 를 한 번 읽어요. 칸이 없으면 null 과 같아요. remote 는 store 와 달리 JSON 글자가 아니라 객체로 넣어요(exams 의 원소도 시험 파일을 읽은 객체예요). 알림에 remote 칸이 없어도 null 로 봐요.
- remote 의 겉모양(seq 는 0 이상의 정수, issuedAt 은 실제로 있는 "YYYY-MM-DDTHH:mm", exams 와 locks 는 배열)이 틀리면 그 remote 는 통째로 쓰지 않고(null 과 같아요) 이유를 개발자 콘솔에 경고로 남겨요(src/exams/merge.ts 의 parseRemote).
- 웹은 remote 의 시험을 하나씩 다시 검사해요(src/exams/validate.ts 의 checkExam, 묶음 안 시험 파일과 같은 검사). 통과하지 못한 시험만 버리고 id 와 이유를 개발자 콘솔에 경고로 남기고, 나머지는 써요. remote.exams 안에 같은 id 가 둘 이상이면 검사를 통과한 것 가운데 앞의 것만 써요.
- 묶음 안 시험과 id 로 합쳐요(src/exams/merge.ts 의 mergeExams). 같은 id 는 rev(판 번호, 없으면 1)가 큰 쪽을 쓰고, 같으면 넘겨받은 쪽을 써요. locks 는 묶음 안 잠금 달력과 id 로 합치고 같은 id 는 넘겨받은 항목을 써요(형식이 틀린 항목은 버려요, src/logic/lock.ts 의 mergeLocks).
- seq 가 지금 쓰는 자료의 seq 와 같거나 작은 remote 는 자료를 바꾸지 않아요. 지금 쓰는 넘겨받은 자료가 없으면(시작할 때 remote 가 null 이었으면) seq 와 상관없이 받아요. 받아들일 때마다 묶음 안 자료와 새로 합쳐요(앞서 넘겨받은 자료와 합치지 않아요).
- 새로 확인의 응답을 10초 기다려요. 보낸 뒤에 처음 온 remote 나 remoteFailed 를 그 응답으로 봐요(껍데기가 요청 없이 보낸 remote 와 구분하지 않아요). 10초 동안 아무 응답이 없으면 remoteFailed 와 같게 다뤄요. 그 뒤에 온 remote 도 자료로는 받아요(seq 규칙대로).
- 넘겨받은 자료는 기록(store.json)에 넣지 않아요. 받아들인 자료를 기기에 보관해 두었다가 다음에 켤 때 remote 로 다시 넣어 주는 것은 껍데기 몫이에요(6-3).
- 넘겨받은 자료로 학생이 넣은 답과 표시를 바꾸지 않아요. 기록이 가리키는 시험을 찾지 못해도 기록을 지우지 않고, 기록 화면의 그 기록 자리와 그 기록을 이어 여는 화면에 "시험 자료를 받으면 다시 볼 수 있어요."를 보여 줘요. 자료가 오면 그 기록을 다시 볼 수 있어요.

### 7-5. 규격을 더할 때

- 메시지나 칸을 더하는 새 규격은 src/platform/app.ts 의 BRIDGE_MAX 를 올리고, 이 문서에 그 번호의 "규격 N" 장을 더하고, 7-2 표의 bridgeMax 값을 고쳐요. 단위 테스트(src/docs.test.ts)가 "규격 N" 장의 가장 큰 번호와 표의 bridgeMax 값이 BRIDGE_MAX 와 같은지 봐요.
- BRIDGE_VERSION(과 문서 제목, 1장 표의 bridge 값)은 예전 규격의 껍데기를 더는 받지 않을 때만 올려요.
