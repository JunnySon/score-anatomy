# 앱 다리 규격 (규격 번호 1)

결론: 아이폰 앱은 화면 전체를 차지하는 웹뷰 하나에 이 저장소의 앱용 묶음(단일 HTML)을 싣는 얇은 껍데기예요. 화면과 계산은 웹 코드가 맡고, 껍데기는 기록 파일 저장, 햅틱, 글자 크기 전달, 복사만 맡아요. 웹과 껍데기는 아래 약속(다리)으로만 주고받아요. 이 문서는 작업 지시서 1의 6-2를 그대로 옮기고, 웹 쪽 구현(src/platform/app.ts)이 실제로 지키는 세부를 더한 것이에요. 작업 지시서 2(iOS 앱 껍데기)가 이 문서를 구현해요.

## 1. 껍데기가 넣어 주는 값

껍데기는 문서가 시작될 때(문서의 다른 스크립트보다 먼저) `window.__SA_APP__` 를 넣어 줘요.

| 칸 | 값 | 뜻 |
| --- | --- | --- |
| platform | "ios" | 껍데기 종류 |
| bridge | 1 | 다리 규격 번호. 이 문서의 번호와 같아야 해요 |
| appVersion | 문자열(예: "0.2.0") | 앱 버전 |
| store | 저장된 JSON 문자열 또는 null | 앱 전용 파일(store.json)의 내용. 파일이 없으면 null |
| fontScale | 1 이상 2 이하의 숫자 | 기기의 글자 크기 설정에서 구한 배율. 기본 크기에서 1 |

`window.__SA_APP__` 가 없으면(브라우저에서 열면) 웹은 지금과 똑같이 동작해요(기록은 localStorage).

## 2. 웹이 껍데기로 보내는 것

`window.webkit.messageHandlers.<이름>.postMessage(값)` 으로 보내요.

| 이름 | 값 | 언제 | 껍데기가 할 일 |
| --- | --- | --- | --- |
| saStore | `{ op: "save", json: 문자열 }` | 저장할 때마다(기록 전체를 JSON 글자 하나로) | store.json 에 저장해요. 요청이 여러 번 오면 순서대로 처리하고 마지막 것이 남아요. 실패하면 원래 파일을 건드리지 않고 storeFailed 로 알려요 |
| saStore | `{ op: "archive" }` | 받은 store 를 읽지 못했을 때, 그 기록을 덮어쓰기 전에 한 번 | store.json 을 지우지 않고 다른 이름으로 보관해요(예: store-보관-날짜시각.json) |
| saHaptic | `"key"` | 받아들인 키패드 누름 한 번에 한 번 | 가벼운 햅틱 한 번. 잠긴 키와 버려진 누름에는 보내지 않아요 |
| saCopy | 복사할 문자열 | 좌표 복사, 진행자용 화면의 복사 | 이 기기의 클립보드에만 넣고 copied 로 결과를 알려요 |

## 3. 껍데기가 웹에 알리는 것

`window.__saFromApp(메시지)` 를 불러요. 웹은 문서가 시작될 때 이 함수를 준비해 둬요.

| 메시지 | 언제 | 웹이 하는 일 |
| --- | --- | --- |
| `{ type: "storeFailed" }` | saStore 의 save 를 저장하지 못했을 때 | 기록 화면에 "이 기기에 기록을 저장하지 못했어요. 화면은 그대로 쓸 수 있어요."를 보여 줘요 |
| `{ type: "fontScale", value: 숫자 }` | 기기의 글자 크기 설정이 바뀌었을 때 | 루트 글자 크기를 바로 바꿔요 |
| `{ type: "copied", ok: 참거짓 }` | saCopy 를 처리한 뒤 | 보낸 차례대로 하나씩 결과로 받아요. ok가 false면 "복사하지 못했어요"를 보여 줘요 |

## 4. 웹이 지키는 것(src/platform/app.ts, src/state/store.ts)

- 앱에서는 localStorage 를 쓰지 않고 다리로만 읽고 써요. 읽기는 시작할 때 `__SA_APP__.store` 를 한 번 읽는 것뿐이에요.
- store 가 null이면 새로 시작해요(보관 요청 없음).
- store 를 통째로 읽을 수 없거나(JSON이 아님, 객체가 아님, version 이 숫자가 아님) version 이 웹이 아는 값(1)보다 크면 덮어쓰지 않아요. archive 를 먼저 보낸 뒤 새로 시작하고, 기록 화면에 "앞서 저장된 기록을 읽지 못해 따로 보관해 뒀어요."를 보여 줘요. 빈 글자("")도 읽을 수 없는 것으로 봐요.
- version 이 1보다 작으면 옮기는 함수를 거쳐요. 지금은 version 1뿐이라 틀만 있고, 옮기지 못하면 읽을 수 없는 것으로 봐요.
- 일부만 망가진 기록(모양이 맞지 않는 칸)은 지금처럼 모양이 맞는 값만 남기고 읽어요. 이때는 보관하지 않아요.
- 저장은 늘 기록 전체를 보내요. 받은 순서대로 쓰면 마지막 것이 지금 상태예요.
- 루트 글자 크기는 16px x fontScale 이에요. 1보다 작은 값은 1로, 2보다 큰 값은 2로, 숫자가 아니면 1로 봐요. 화면의 글자 크기는 모두 rem 이라 함께 커져요.
- copied 를 3초 안에 받지 못하면 복사하지 못한 것으로 봐요.
- 앱 안에서만 바꾸는 문구: 시작 화면 "가입 없이 써요. 기록은 이 기기에 저장하고 서버로 보내지 않아요.", 기록 화면 아래 "앱을 지우면 기록도 함께 지워져요.", 저장 실패 문구. 진행자용 화면(시험용 묶음)은 "파일 저장" 버튼을 빼고 복사만 둬요.
- 길게 눌렀을 때 글자 선택이나 미리보기가 뜨지 않게 하고(글을 적는 칸과 좌표 목록은 빼고), 화면 끝에서 당겨도 화면 전체가 끌려오지 않게 해요(html.sa-app 의 CSS). 껍데기도 웹뷰의 미리보기와 튕김을 꺼 주면 좋아요.
- 바깥으로 나가는 요청은 없어요. 묶음은 글꼴, 스크립트, 스타일을 모두 파일 안에 담고 있어요.

## 5. 묶음 파일

| 파일 | 뜻 |
| --- | --- |
| ios/ScoreAnatomy/Web/app-test/index.html | 시험용 묶음. 진행자용 화면과 입력 방식 전환을 포함해요. 사용성 테스트를 아이폰에서 할 때 써요(Debug 빌드) |
| ios/ScoreAnatomy/Web/app-release/index.html | 배포용 묶음. 진행자용 화면과 그리로 가는 링크, 입력 방식 전환과 5행 방식 화면, 기록 화면의 "준비 중인 기능" 목록이 묶음 안의 코드와 글자에서 빠져 있어요(Release 빌드) |
| ios/ScoreAnatomy/Web/manifest.json | 묶음을 만든 때의 커밋(commit, 그때 커밋하지 않은 바뀜이 있었는지 dirty), package.json 의 버전(version), 다리 규격 번호(bridge), 파일별 SHA-256 과 크기(files) |

- 셋 다 커밋해요. 맥에서는 Node 없이 이 파일만 써요.
- 만드는 명령은 `npm run build:app` 이에요. 같은 코드에서는 같은 묶음(같은 SHA-256)이 나와요. `npm run verify` 가 지금 코드로 다시 만들어 커밋된 묶음과 같은지 확인해요.
- 줄바꿈 변환으로 바이트가 바뀌지 않게 .gitattributes 에서 이 폴더를 -text 로 둬요.

## 6. 규격을 바꿀 때

- 웹과 껍데기 가운데 한쪽만 바뀌는 변경(메시지 추가, 값의 뜻 변경)은 규격 번호를 올리고 이 문서, src/platform/app.ts 의 BRIDGE_VERSION, scripts/app-bundles.mjs 의 BRIDGE_VERSION 을 함께 고쳐요.
- 껍데기는 `__SA_APP__.bridge` 로 웹이 기대하는 번호를 알려 주고, 웹은 manifest.json 의 bridge 로 묶음이 따르는 번호를 알려요.
