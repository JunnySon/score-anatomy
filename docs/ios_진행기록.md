## 중간에 찾아 고친 것

- 웹뷰를 App 을 만들 때 만들면 첫 누름에서 앱이 꺼졌다(iOS 18.4, 26.4). 창이 뜬 뒤에 만들게 고침.
- Swift 전용 WebKit 함수가 libswiftWebKit 을 불러 iOS 18.4 에서 켜자마자 꺼졌다. evaluateJavaScript 로 바꿈.
- 시뮬레이터의 시스템 밝기 바꾸기(simctl, XCUIDevice)가 앱에 닿지 않아 어두운 화면 캡처는 DEBUG 실행 인자로 앱의 밝기를 정함.
- 링크로 가는 이동에서 WebKit 이 내용 없는 TCP 연결을 미리 맺는 것을 찾음(요청 내용 0, 웹 묶음에 바깥 링크 0). 탐침을 하위 자원과 이동으로 나눠 셈.
- iPhone SE 에서 등급 칩이 아래 고정 버튼에 가려 화면 테스트의 누름이 빗나갔다. 칩을 가운데로 옮긴 뒤 누르게 고침.
- verify.sh 가 만든 시뮬레이터를 지우지 못했다(하위 셸에서 목록을 모음). 부르는 쪽에서 모으고 이름으로도 지우게 고침.
- 참고 캡처를 모을 때 한글 파일 이름의 유니코드 정규화(NFD, NFC)가 달라 목록 캡처까지 복사됐다. 정규화를 맞춤.
- 저장소가 데스크톱 폴더에 있어 XCTest 가 실패를 기록하다 멈췄다(빌드 중간 파일을 열다 막힘, 한글 경로 탓은 아님). verify.sh 의 테스트 빌드에만 디버그 맵을 빼는 링커 설정(-Wl,-S)을 더하고 확인함(처음 쓴 -oso_prefix 는 한글 정규화 때문에 빌드에 따라 적용되지 않았음).

### 누름 만들기 장치에서 찾은 것(19:20~19:50, 개발용 시뮬레이터)

10. 남은 것. iPhone 17 / iOS 26.4.1에서 먼저 진행자 측정 중 3번 표시 칸을 두 번(419ms 간격) 눌러 “고민”이 남는 경우, 빈 키패드에서 답 3을 세 번(678ms, 67ms 간격) 눌러 1번에만 저장되는 경우를 웹 쪽에서 재현해요. 두 경우 모두 손가락 click 1개, 채움 0개였어요. 독립 3-1의 표시 칸 두 번에서도 iPhone 16 / iOS 18.4는 0개 2회와 1개 2회, iPhone 17 / iOS 26.4.1은 1개 1회였어요. 전체 verify의 새 180회에서는 iPhone 17에서 표시 칸을 세 번 눌러 2개만 들어간 회차도 10회 중 2회였어요. 웹 수정본으로 같은 검사와 전체 verify를 통과한 뒤 PR 병합 조건을 다시 확인해요. 11. 사람이 정하거나 할 것. 실제 아이폰에서 확인표 33개를 채워요. 이번 29~33번은 앱을 막 켠 뒤 빠른 두 번 누름, 두 손가락 확대, 버튼 위에서 시작한 스크롤, 길게 누름, VoiceOver 실행이에요. 실제 기기와 서명 빌드, 시험 받는 주소와 운영 키, Apple 계정과 배포 설정은 사람에게 남아 있어요. [실기기 확인표](ios_실기기_확인표.md#2-확인표)
12. 작업 폴더 상태. ios-remote에서 공식 실행의 시작과 결과 산출 시점에 검증 소스는 깨끗했어요. 기존 ios-v1 문서 4개가 담긴 stash 한 개를 보존했고 이번에 더한 stash는 없어요. 전체 verify가 만든 임시 시뮬레이터와 로컬 시험 서버를 정리했어요.
