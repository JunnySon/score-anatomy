# iOS 화면 비교

결론: iOS 캡처(docs/screens-ios) 36장을 같은 화면의 웹 캡처(docs/screens)와 나란히 놓고 모두 직접 봤어요. 글자, 색, 무늬, 버튼 배치는 밝은 화면과 어두운 화면 모두 웹과 같았어요. 차이는 아이폰의 안전 영역(위 상태 표시줄, 아래 홈 표시 자리)에서 온 것과, 앱 안에서만 바꿔 쓰는 문구, 화면 폭 차이로 생긴 줄바꿈이 대부분이에요. 고쳐야 할 껍데기 문제는 없었고, 웹 쪽에서 판단할 거리 두 가지(키패드 판 아래 띠, 등급을 고른 뒤 첫 줄이 화면 아래로 내려감)를 아래에 적었어요. 웹 파일은 고치지 않았어요.

## 비교한 방법

- iOS 캡처: verify.sh 의 CaptureTests 가 iPhone 17(402 x 874pt, 화면 1206 x 2622)과 iPhone SE 3세대(375 x 667pt, 화면 750 x 1334)에서 밝은 화면과 어두운 화면으로 9화면씩 찍었어요. 상태 표시줄 시각은 9:41 로 고정했어요.
- 웹 캡처: docs/screens/light, dark(390 x 844, 2배)와 docs/screens/small(360 x 640, 1배, 밝은 화면만).
- 짝: 01-시작과 01-시작, 02-시험선택과 04-시험선택, 03-답입력-키패드와 08-답입력-키패드-객관식, 04-잠금과 10-답입력-키패드-잠금, 05-입력확인과 17-입력확인, 06-표시와 22-표시-붙임, 07-점수해부와 27-점수해부-2등급, 08-계단과 32-계단, 09-기록과 43-기록.
- 같은 높이로 줄여 한 장에 나란히 붙여(iOS 밝은 화면, 웹 밝은 화면, iOS 어두운 화면, 웹 어두운 화면) 한 장씩 열어 봤어요. 붙인 그림은 저장소에 넣지 않았어요.
- 어두운 화면은 DEBUG 실행 인자로 앱의 밝기를 정해 찍었어요(이 맥의 시뮬레이터에서는 시스템 밝기 바꾸기가 앱에 닿지 않았어요, docs/ios_결정기록.md). 켤 때 화면과 상태 표시줄은 실기기 확인표 16번에서 사람이 봐요.

## iPhone 17

| 화면 | 차이 | 판단 | 이유 |
| --- | --- | --- | --- |
| 모든 화면 | 위쪽 상태 표시줄 자리(약 62pt)만큼 내용이 아래에서 시작하고, 아래 탭은 홈 표시 자리(약 34pt) 위에 놓여요. 그만큼 한 화면에 보이는 양이 줄어요 | 그대로 둠 | 웹이 안전 영역 값(env(safe-area-inset-*))으로 처리한 결과예요. 글자나 버튼이 상태 표시줄, 홈 표시와 겹치지 않아요 |
| 01 시작 | 아래 안내가 "가입 없이 써요. 기록은 이 기기에 저장하고 서버로 보내지 않아요."(웹은 "... 이 기기에만 남아요.") | 그대로 둠 | 다리 규격 4장의 앱 안에서만 바꾸는 문구예요 |
| 02 시험 선택 | 예시 시험 C 카드의 설명 줄바꿈 위치가 달라요(iOS 는 "22~30번" 뒤에서, 웹은 "5지선다," 뒤에서) | 그대로 둠 | 화면 폭(402pt 와 390pt) 차이로 생긴 자연스러운 줄바꿈이에요. 잘린 글자는 없어요 |
| 03 답 입력(키패드) | 키패드 판(표면색 바탕)이 키 바로 아래에서 끝나고, 그 아래 홈 표시 자리(약 34pt)는 화면 바탕색이에요. 웹 캡처에는 이 자리가 없어요 | 웹 쪽 판단(제안) | 키는 모두 보이고 눌리며, 키가 홈 표시와 떨어져 있어 오히려 실수로 홈으로 나갈 일이 적어요. 키패드 판 바탕을 아래 끝까지 이어 보이게 하려면 웹의 키패드 판 안쪽 아래 여백에 안전 영역 값을 넣으면 돼요 |
| 04 잠금 | 03 과 같은 아래 띠. 잠긴 키(점선), 안내문, "10번도 고치기", "12번부터 이어서 넣기"는 웹과 같아요 | 03 과 같음 | |
| 05 입력 확인 | 차이 없음(안전 영역 말고) | 그대로 둠 | 30칸과 "맞아요, 다음으로"가 한 화면에 들어와요 |
| 06 표시 | 웹 캡처는 아래로 내린 상태(단답형과 시간 질문), iOS 캡처는 맨 위(5지선다 격자)를 찍었어요. 겹치는 부분(11~21번 칸의 빗금과 고민 윤곽)은 같아요 | 그대로 둠 | 캡처 위치의 차이예요. 25번 "자신 없음"과 "빠듯했어요"는 캡처 테스트가 눌러서 확인했어요(아래 화면은 화면 테스트가 확인) |
| 07 점수 해부 | 2등급을 고른 뒤 첫 줄("실제 78점 기준 3~7점 남았어요")이 첫 화면 아래로 내려가 스크롤해야 보여요. 웹 캡처에서는 반쯤 보여요 | 웹 쪽 판단(제안) | 안전 영역만큼 세로가 줄어서예요. 아이폰 Safari 에서도 비슷해요. 목표 등급을 고르면 등급컷 상자가 화면 안으로 들어오게 스크롤하면 첫 줄을 바로 볼 수 있어요 |
| 08 계단 | 카드 이유 문장의 줄바꿈 위치가 조금 달라요 | 그대로 둠 | 화면 폭 차이예요 |
| 09 기록 | 맨 아래 "앱을 지우면 기록도 함께 지워져요."가 더 있어요 | 그대로 둠 | 앱 안에서만 쓰는 문구예요. 시험용 묶음이라 "준비 중인 기능"과 "테스트 진행자용"이 보이는 것은 웹 캡처와 같아요(배포용 묶음에서는 빠지는 것을 ReleaseSmokeTests 가 확인해요) |
| 어두운 화면 전체 | 배경 #111315, 글자, 포인트색, 무늬가 웹의 어두운 화면과 같아요 | 그대로 둠 | |
