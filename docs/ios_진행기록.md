## 중간에 찾아 고친 것

- 웹뷰를 App 을 만들 때 만들면 첫 누름에서 앱이 꺼졌다(iOS 18.4, 26.4). 창이 뜬 뒤에 만들게 고침.
- Swift 전용 WebKit 함수가 libswiftWebKit 을 불러 iOS 18.4 에서 켜자마자 꺼졌다. evaluateJavaScript 로 바꿈.
- 시뮬레이터의 시스템 밝기 바꾸기(simctl, XCUIDevice)가 앱에 닿지 않아 어두운 화면 캡처는 DEBUG 실행 인자로 앱의 밝기를 정함.
- 링크로 가는 이동에서 WebKit 이 내용 없는 TCP 연결을 미리 맺는 것을 찾음(요청 내용 0, 웹 묶음에 바깥 링크 0). 탐침을 하위 자원과 이동으로 나눠 셈.
- iPhone SE 에서 등급 칩이 아래 고정 버튼에 가려 화면 테스트의 누름이 빗나갔다. 칩을 가운데로 옮긴 뒤 누르게 고침.
- verify.sh 가 만든 시뮬레이터를 지우지 못했다(하위 셸에서 목록을 모음). 부르는 쪽에서 모으고 이름으로도 지우게 고침.
- 참고 캡처를 모을 때 한글 파일 이름의 유니코드 정규화(NFD, NFC)가 달라 목록 캡처까지 복사됐다. 정규화를 맞춤.
- 저장소가 데스크톱 폴더에 있어 XCTest 가 실패를 기록하다 멈췄다(빌드 중간 파일을 열다 막힘, 한글 경로 탓은 아님). verify.sh 의 테스트 빌드에만 디버그 맵을 빼는 링커 설정(-Wl,-S)을 더하고 확인함(처음 쓴 -oso_prefix 는 한글 정규화 때문에 빌드에 따라 적용되지 않았음).

### 누름 만들기 장치에서 찾은 것(19:20~19:50, 개발용 시뮬레이터)

- XCUITest 의 비공개 장치(XCPointerEventPath, XCSynthesizedEventRecord)로 0.1~1초 간격의 두 번 누름을 만들어 보냈더니, 정한 간격과 상관없이 웹에는 앞 손뗌 0ms 뒤에 다음 누름이 왔어요(누름 시작 사이 66ms). 손가락 번호를 다르게 해도, 누른 동안 움직임을 넣어도 같았어요.
- 한 손가락 길에서 떼었다 다시 누르면 중간 손뗌이 사라져 길게 누른 하나가 됐어요.
- 기록을 따로 보내면 누름 시작 사이가 0.28~0.30초 밑으로 내려가지 않았어요. 확인 간격을 5초에서 0으로 줄여도 같았어요. 비동기로 보낸 둘째 기록은 앞 기록이 끝나기 전이면 버려졌어요.
- 그래서 0.1초와 0.2초 간격은 확인하지 못함으로 두고, 아주 빠름(doubleTap), 가장 짧게 따로 보낸 누름(약 0.29초), 0.4초, 0.5초를 실제로 잰 값과 함께 적어요(결정기록 4장).
- 시험에 쓴 임시 코드(ProbeSynth)는 지웠어요.
